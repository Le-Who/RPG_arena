## 🌟 Почему Chronicle Engine?

Текстовой RPG с генеративной моделью важно сохранять канон, управлять AI-вызовами и согласовывать свободные действия с состоянием мира. В Chronicle Engine для этого уже есть следующие механизмы и ограничения:

| Область | Текущая реализация |
| :--- | :--- |
| **Память** | Пять логических слоёв, ранжирование нод, ограниченный дайджест и компакция; новые кандидаты пока извлекаются эвристически по словам |
| **AI-вызовы** | Профили роутинга Gemini, логирование и ротация ключей; отображаемые лимиты не ограничиваются сервером |
| **Свободное действие** | Для live-resolution текущего d20-профиля сервер бросает кубик до AI; offline-engine делает отдельный процедурный бросок |
| **Структурированный вывод** | Resolution запрашивается как JSON через Gemini responseSchema, затем разбирается fallback-парсером; полной runtime-валидации нет |
| **Офлайн-фолбэк** | Текущая версия запускает процедурный движок после ошибки AI или без ключей; границы для preset/free ещё предстоит разделить |
| **Состояние мира** | Сессии, память, инвентарь и локации хранятся в PostgreSQL, но предметы и переходы между локациями пока не полностью применяются к игре |

### 🧠 Древо памяти Memory House (5 слоёв)

Вместо наивного накопления всей истории чата в промпте Chronicle Engine хранит память в пяти логических слоях. Текущая реализация ранжирует до 60 нод, вставляет недавние ходы отдельно и ограничивает дайджест памяти по tier модели; это не жёсткое глобальное ограничение каждого промпта.

```
┌────────────────────────────────────────────────────────────────────────┐
│                  MEMORY HOUSE (текущие reference-бюджеты)              │
├───────────────────┬───────────────┬────────────────────────────────────┤
│ Слой              │ Бюджет        │ Содержимое и назначение            │
├───────────────────┼───────────────┼────────────────────────────────────┤
│ ⚡ Working        │ 4 000 токенов │ Недавние ходы, передаются отдельно │
│ 📖 Episodic       │ 5 000 токенов │ События, развилки, клятвы, ранения │
│ 🧠 Semantic       │ 4 000 токенов │ Факты о мире, NPC, предметы        │
│ ⚙️ Procedural     │ 2 000 токенов │ Правила, статы, модификаторы       │
│ 📜 Chronicle      │ 3 500 токенов │ Итоги глав и ключевые вехи         │
└───────────────────┴───────────────┴────────────────────────────────────┘
```

- **Importance & Salience**: Ноды ранжируются по важности и свежести; точные значения зависят от источника ноды.
- **Взвешенное ранжирование**: Выборка top-60 нод строится по формуле `importance × 0.7 + salience × 0.3`; высокий salience помогает свежим фактам конкурировать со старыми важными событиями.
- **Компакция**: Запускается после 24 реальных действий игрока с последней компакции либо когда оценка недавних ходов превышает 4 000 токенов для Lite или 8 000 для Flash. Сам дайджест памяти ограничен 8 000/14 000 символами соответственно.
- **Извлечение кандидатов**: после хода текущая версия ищет слова и шаблоны в тексте действия игрока и ответе рассказчика. Слово «золото» из item-keywords исключено, но оставшиеся ключевые слова всё ещё могут создавать ложные или жанрово узкие воспоминания; это не семантическая проверка факта изменения состояния. AI-компакция не заменяет такой extractor. Целевой переход на канонические события и semantic-extractor описан в [MEM-1](docs/superpowers/plans/roadmap.md).

### ⚡ Маршрутизация Gemini

Приложение хранит четыре профиля маршрутизации: Balanced, Economy, Flagship и Custom. Значения `20` и `500` используются в конфигурации и подписях, а дашборд отдельно показывает для Flash `/60`; эти числа не согласованы между собой и не ограничиваются сервером как квоты. Их сверка и унификация отмечены в [DATA-1d](docs/superpowers/plans/roadmap.md). Фактическая доступность модели определяется ответом Gemini и подключёнными ключами.

Текущая маршрутизация выглядит так:

```
┌──────────────────────────┬───────────────────────────────┬────────────────────────────┐
│ Игровая задача           │ Модель                        │ Назначение                 │
├──────────────────────────┼───────────────────────────────┼────────────────────────────┤
│ Обычный ход (1 / 2 / 3)  │ Lite по умолчанию             │ Экономичный нарратив       │
│ Свободное действие       │ Flash 3.8 по умолчанию        │ Resolution JSON + pre-roll │
│ Компакция памяти         │ Настроенный Flash             │ Сжатие накопленных ходов   │
│ Быстрая задача           │ Настройка есть, вызова пока нет│ Будущий extraction         │
│ Фолбэк                   │ Другой ключ/модель, затем offline-engine │ Продолжение текущей версии │
└──────────────────────────┴───────────────────────────────┴────────────────────────────┘
```

#### Готовые профили маршрутизации в интерфейсе:
1. ⚡ **Баланс & Экономия (Рекомендуемый)**: Lite 3.5 для обычных ходов, Flash 3.8 для свободных действий и компакции.
2. 🌿 **Максимальная Экономия**: Lite 3.5 для обычных и свободных ходов; Flash остаётся для компакции.
3. 👑 **Флагманский**: Flash 3.8 на все действия для максимальной художественной детализации.
4. ⚙️ **Custom**: Ручной выбор модели под каждую из четырёх задач.

#### Пул ключей и ротация:
При ошибке модели или ключа движок пробует следующий ключ, затем следующую модель своей цепочки. Для свободного действия цепочка по умолчанию включает `3.8 → 3.7 → 3.6 → Lite`; при окончательной ошибке текущая версия запускает offline-engine. Плановое ограничение фолбэка preset-кампаниями описано в [roadmap](docs/superpowers/plans/roadmap.md).

> Значения `20/60/500` — внутренние показатели интерфейса и конфигурации, не серверный ограничитель запросов и не гарантия тарифа Gemini. Перед production-использованием их нужно сверить с провайдером.

### 🎲 Серверный d20 — бросок до нарратива

В текущей версии live свободное действие игрока использует упрощённый серверный d20-профиль. Сервер **сначала** рассчитывает результат броска, и **только потом** вызывает AI, поэтому модель получает уже зафиксированный исход. Если live AI недоступен, current offline-engine разрешает действие собственной процедурной логикой и отдельным броском. Это не полная реализация D&D 5e и не универсальная механика для будущих кампаний.

```
Игрок вводит действие
        ↓
detectSkill(action)          → эвристически определяет навык и стат (СИЛ/ЛОВ/ИНТ/…)
statModifier(stat)           → модификатор по текущей формуле
dcFor(danger, turn)          → динамическая сложность DC
rollD20(skill, modifier, dc) → физический бросок d20 на сервере
        ↓
Факт броска передаётся в системный промпт:
  «d20=14+2=16 vs DC 13 — УСПЕХ (Скрытность)»
        ↓
Системный промпт требует нарратив под известный исход
  (сервер не валидирует художественный текст отдельно)
```

- **6 текущих характеристик**: Сила (СИЛ), Ловкость (ЛОВ), Выносливость (ВЫН), Интеллект (ИНТ), Мудрость (МУД), Харизма (ХАР).
- **Модификаторы статов**: $\text{Modifier} = \lfloor \frac{\text{Stat} - 10}{2} \rfloor$
- **Динамическая сложность (DC)**: Масштабируется от текущего уровня опасности локации и номера хода:
  $$\text{DC} = \min(20,\ 10 + \operatorname{round}(\frac{\text{Danger}}{25}) + \min(3, \lfloor \frac{\text{Turn}}{8} \rfloor))$$
- **Критические исходы**: натуральная **20** принудительно даёт успех, натуральная **1** — неудачу. Награды и последствия в live-resolution пока не имеют отдельного серверного правила для критов.
- **Механика смерти**: если после применённых эффектов HP достигает 0, герой остаётся в истории с 1 HP, а золото уменьшается максимум на 10.

Выбор других механических профилей — `rules-light` и `narrative` — зафиксирован как развитие проекта в [roadmap](docs/superpowers/plans/roadmap.md).

### 📐 Structured Output (responseSchema)

Для свободных действий (`custom: true`) сервер передаёт в Gemini API `responseSchema` и `responseMimeType: "application/json"`. Это направляет провайдера к JSON-ответу без markdown-обёрток, но не заменяет runtime-валидацию на сервере:

```json
{
  "outcome": "success | partial | failure",
  "dc": 13,
  "roll_reason": "Скрытность",
  "narration": "120-200 слов...",
  "effects": { "hp": -5, "xp": 30, "gold": 0, "flags": {} },
  "loot": [{ "name": "...", "kind": "misc", "description": "..." }],
  "choices": ["Вариант 1", "Вариант 2", "Вариант 3"]
}
```

После ответа сервер выполняет `JSON.parse` и при невалидном/несхемном ответе использует fallback-парсер (`startsWith("{")` + `indexOf/lastIndexOf`). Полной runtime-валидации и типизированного применения state changes пока нет — это задача [RES-1](docs/superpowers/plans/roadmap.md).

В текущей схеме также нет структурированных изменений локации и квестов: переход можно описать в narration, но сервер не сохранит его как состояние мира. Инвентарь и локации сохраняются и отображаются, однако список имеющихся предметов не передаётся в AI-промпт, использование/списание вещей не обрабатывается, а переходы между локациями не применяются. Сейчас сервер добавляет выданный лут; полноценное применение предметов и изменений мира отслеживается в [INV-1](docs/superpowers/plans/roadmap.md) и [RES-1](docs/superpowers/plans/roadmap.md).

### Направление развития

Текущая реализация использует режимы `preset` и `custom`, но custom-кампания пока разделяет с пресетами d20-механику и универсальный офлайн-фолбэк. Целевой продукт отделит строго спроектированные preset-истории от AI-first free-кампаний и позволит выбирать профиль механик: `d20`, `rules-light` или `narrative`. Полная спецификация и порядок реализации находятся в [roadmap](docs/superpowers/plans/roadmap.md).

## 🚀 Быстрый старт (Quick Start)

### Требования
- **Node.js** >= 20.x
- **PostgreSQL** >= 14.x (локально или через облако Supabase / Neon)
- (Опционально) API-ключ **Google AI Studio** ([получить бесплатно](https://aistudio.google.com/))

### 1. Клонирование репозитория
```bash
git clone https://github.com/Le-Who/RPG_arena.git
cd RPG_arena
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Настройка переменных окружения
Скопируйте файл конфигурации:
```bash
cp .env.example .env
```

Отредактируйте `.env`, указав строку подключения к вашей базе данных PostgreSQL:
```env
DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5432/app_db"
```

### 4. Запуск сервера разработки
```bash
npm run dev
```

> **Текущий запуск миграций:** при старте `instrumentation.ts` вызывает runner, который читает SQL-файлы из `drizzle/` и пытается применить их по одному. Ошибки логируются, но не останавливают сервер. Это ещё не versioned migration ledger и не гарантированно идемпотентный production-процесс; его исправление отслеживается в [DATA-1](docs/superpowers/plans/roadmap.md).

Откройте в браузере: **`http://localhost:3000`**

### 5. Добавление API-ключей Gemini
1. Перейдите в раздел **`Настройки`** (`/settings`).
2. Вставьте один или несколько ключей Google AI Studio в поле добавления.
3. Выберите рекомендуемый профиль **«Баланс & Экономия»**.
4. Включите тумблер **«Live Gemini: ВКЛ»**. Без ключей текущая версия использует автономный offline-engine; в будущем этот путь будет ограничен preset-кампаниями — см. [roadmap](docs/superpowers/plans/roadmap.md).

## 🖥️ Страницы и возможности интерфейса

- **Лобби кампаний (`/`)**:
  - Карточки 6 готовых миров с выбором архетипов (Следопыт, Клирик, Плут, Нетраннер, Самурай, Адвокат и др.).
  - Редактор создания custom-истории с описанием мира и героя.
- **Игровая комната (`/play/[id]`)**:
  - **Лог хроники**: ответы мастера, реплики игрока и отдельные плашки бросков с результатом/DC.
  - **Панель действий**: предложенные варианты и поле авторского свободного ввода с d20-разрешением.
  - **Инспектор героя**: статы, опыт, уровень, динамическая шкала HP, рюкзак и экипировка.
  - **SVG-карта**: сохранённые локации, координаты, индикаторы опасности, туман войны и текущая отметка.
  - **Вкладка Memory House**: API загружает до 60 наиболее важных нод; интерфейс показывает до 8 нод на слой и кнопку ручной компакции.
- **Центр управления (`/settings`)**:
  - Пул маскированных ключей с ротацией.
  - Переключение 4 профилей роутинга.
  - Матрица кастомного назначения моделей на 4 типа задач.
  - Мониторинг вызовов, токенов, ошибок и отображаемых лимитов по моделям.
- **Архитектурный манифест (`/blueprint`)**:
  - Исчерпывающий интерактивный разбор направлений, механизмов, факторов и компромиссов проекта.

| `POST` | `/api/sessions` | Создание новой кампании (пресет или кастомный мир) |
| `GET` | `/api/sessions/:id` | Снимок кампании: сессия, последние 60 записей ходов, до 60 нод памяти, инвентарь и локации |
| `DELETE` | `/api/sessions/:id` | Удаление кампании и связанных данных |
| `POST` | `/api/sessions/:id/act` | Совершение хода; `custom: true` — свободное действие с pre-roll d20 и Gemini responseSchema при live AI, иначе offline-engine |
| `POST` | `/api/sessions/:id/compact` | Запуск компакции памяти через старшие Flash-модели |
| `GET` | `/api/sessions/:id/memories` | Статистика узлов памяти по 5 слоям и оценка токенов |
| `GET` | `/api/settings` | Текущие настройки роутинга, профили и маскированные ключи |
| `POST` | `/api/settings` | Обновление ключей, профилей и лимитов |
| `GET` | `/api/tokens/stats` | Агрегированная статистика токенов и вызовов за текущие сутки |
| `GET` | `/api/health` | Health-check эндпоинт (статус сервера) |

### Тело запроса `POST /api/sessions/:id/act`

```typescript
{
  action: string,  // текст действия (max 2000 символов)
  custom: boolean  // true = свободное действие (pre-roll перед live AI; offline-engine без AI)
                   // false = выбор из 3 предложенных вариантов (нарративный режим)
}
```
