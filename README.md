## 🌟 Почему Chronicle Engine?

Большинство существующих текстовых AI-игр страдают от трёх критических проблем: они либо раздувают контекст до галлюцинаций, либо быстро исчерпывают квоты бесплатных API, либо слепо соглашаются на любое абсурдное действие игрока (*AI Yes-Manning*). 

**Chronicle Engine устраняет эти ограничения системно:**

| Параметр | Обычные AI-игры | Chronicle Engine |
| :--- | :--- | :--- |
| **Управление памятью** | Бесконечный контекст (250k+ токенов), ведущий к деградации и потере фактов | **Memory House**: 5-уровневая иерархическая память с жестким бюджетом в 17k токенов и умной компакцией |
| **Экономика квот** | Все ходы отправляются в одну флагманскую модель, сжигая дневной лимит за 15 минут | **Двухуровневый роутер**: Lite 3.5 (500 req/day) для рутины + Flash 3.8 (20 req/day) для кульминаций. Экономия квот до **25×** |
| **Честность и правила** | Модель выдумывает исход на глаз («Я победил дракона ложкой — ок») | **Серверный d20 бросается ДО вызова AI**: факт броска (DC, roll, результат) передаётся в промпт — AI только описывает уже известный исход |
| **Структурированный вывод** | AI возвращает свободный текст, парсинг хрупок | **Gemini responseSchema** гарантирует чистый JSON без markdown-обёрток для resolution-задач |
| **Отказоустойчивость** | Ошибка сети или лимита (HTTP 429) ломает игровую сессию | **Ротация 10 ключей** + встроенный **процедурный офлайн-движок** |
| **Постоянство мира** | Инвентарь и локации существуют только в воображении нейросети | Строгий граф состояния, инвентарь и интерактивная SVG-карта в **PostgreSQL** |

### 🧠 Древо памяти Memory House (5 слоёв)

Вместо наивного накапливания всей истории чата в контекст промпта, Chronicle Engine организует воспоминания по модели когнитивной психологии. Контекстный сборщик строго удерживает суммарный размер промпта в пределах **17 000 токенов**, исключая падение качества генерации:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        MEMORY HOUSE (БЮДЖЕТ 17k)                       │
├───────────────────┬───────────────┬────────────────────────────────────┤
│ Слой              │ Бюджет        │ Содержимое и назначение            │
├───────────────────┼───────────────┼────────────────────────────────────┤
│ ⚡ Working        │ 6 000 токенов │ Последние N ходов дословно         │
│ 📖 Episodic       │ 4 000 токенов │ События, развилки, клятвы, ранения │
│ 🧠 Semantic       │ 3 000 токенов │ Факты о мире, NPC, артефакты, базы │
│ ⚙️ Procedural     │ 1 500 токенов │ Правила мира, статы, модификаторы  │
│ 📜 Chronicle      │ 2 500 токенов │ Несгораемая летопись рубежей глав  │
└───────────────────┴───────────────┴────────────────────────────────────┘
```

- **Importance & Salience**: Каждый факт оценивается по шкале важности (упоминания смертей, клятв, артефактов получают приоритет `>= 75`) и свежести.
- **Взвешенное ранжирование**: Выборка top-60 нод строится по формуле `importance × 0.7 + salience × 0.3` — это гарантирует, что свежие NPC-ноды (высокий salience) не вытесняются старыми событиями с высоким importance.
- **Автоматическая компакция**: Когда рабочая память заполняется или сессия достигает 14 ходов, старшая модель синтезирует ключевые события в узлы эпизодической памяти и летописи, отсекая воду.

### ⚡ Двухуровневая маршрутизация Gemini (Стратегия 20 vs 500)

Google Gemini предоставляет щедрые, но несбалансированные квоты в бесплатном тарифе: **20 запросов в день** на флагманские модели серии Flash (3.8, 3.7, 3.6) и **500 запросов в день** на экономичную Flash-Lite 3.5. 

Chronicle Engine применяет специализированное разделение труда:

```
┌──────────────────────────┬─────────────────────────────┬──────────────┬───────────────────────────────┐
│ Игровая задача           │ Модель                      │ Квота        │ Почему именно она             │
├──────────────────────────┼─────────────────────────────┼──────────────┼───────────────────────────────┤
│ Обычный ход (1 / 2 / 3)  │ gemini-3.5-flash-lite       │ 500 req/day  │ Мгновенный отклик, экономия   │
│ Свободное действие       │ gemini-3.8-flash            │ 20 req/day   │ Глубокий анализ, JSON-схема   │
│ Компакция памяти         │ gemini-3.8-flash / 3.7      │ 20 req/day   │ Категорический запрет потерь  │
│ Извлечение фактов и лута │ gemini-3.5-flash-lite       │ 500 req/day  │ Структурирование данных       │
│ Аварийный режим          │ offline-engine              │ ∞ безлимитно │ Процедурные шаблоны + d20     │
└──────────────────────────┴─────────────────────────────┴──────────────┴───────────────────────────────┘
```

#### Готовые профили маршрутизации в интерфейсе:
1. ⚡ **Баланс & Экономия (Рекомендуемый)**: Lite 3.5 для ходов + Flash 3.8 только для авторских действий и сжатия памяти.
2. 🌿 **Максимальная Экономия**: Lite 3.5 для всех ходов, Flash привлекается исключительно на рубежах глав.
3. 👑 **Флагманский**: Flash 3.8 на все действия для максимальной художественной детализации.
4. ⚙️ **Custom**: Ручной выбор модели под каждую из четырёх задач.

#### Пул ключей и ротация:
Система поддерживает пул до 10 API-ключей Google AI Studio. При получении ошибки `429 (Resource Exhausted)` движок моментально переключается на следующий ключ, а при исчерпании пула — спускается по фолбэк-цепочке (`3.8 → 3.7 → 3.6 → Lite → Offline`).

### 🎲 Серверный D&D d20 Engine — бросок ДО нарратива

Движок не позволяет нейросети самостоятельно «придумывать» успех действия. При свободном действии игрока сервер **сначала** рассчитывает результат броска, и **только потом** вызывает AI:

```
Игрок вводит действие
        ↓
detectSkill(action)          → определяет навык и стат (СИЛ/ЛОВ/ИНТ/…)
statModifier(stat)           → модификатор по D&D формуле
dcFor(danger, turn)          → динамическая сложность DC
rollD20(skill, modifier, dc) → физический бросок d20 на сервере
        ↓
Факт броска передаётся в системный промпт:
  «d20=14+2=16 vs DC 13 — УСПЕХ (Скрытность)»
        ↓
Gemini пишет нарратив ПОД известный исход
  (не может противоречить факту броска)
```

- **6 классических характеристик**: Сила (СИЛ), Ловкость (ЛОВ), Выносливость (ВЫН), Интеллект (ИНТ), Мудрость (МУД), Харизма (ХАР).
- **Модификаторы статов**: $\text{Modifier} = \lfloor \frac{\text{Stat} - 10}{2} \rfloor$
- **Динамическая сложность (DC)**: Масштабируется от текущего уровня опасности локации и номера хода:
  $$\text{DC} = \min(20,\ 10 + \lfloor \frac{\text{Danger}}{25} \rfloor + \lfloor \frac{\text{Turn}}{8} \rfloor)$$
- **Критические исходы**: 
  - Натуральная **20** — триумфальный успех с утроенным опытом и уникальным лутом.
  - Натуральная **1** — критический провал с серьёзным уроном и потерей инициативы.
- **Механика смерти**: При 0 HP герой не стирается, а пробуждается на грани гибели ценой штрафа золота.

### 📐 Structured Output (responseSchema)

Для свободных действий (`custom: true`) сервер передаёт в Gemini API `responseSchema` и `responseMimeType: "application/json"`. Это гарантирует строго типизированный ответ без markdown-обёрток:

```json
{
  "outcome": "success | partial | failure",
  "dc": 13,
  "roll_reason": "Скрытность",
  "narration": "120-200 слов...",
  "effects": { "hp": -5, "xp": 30, "gold": 0 },
  "loot": [{ "name": "...", "kind": "misc", "description": "..." }],
  "choices": ["Вариант 1", "Вариант 2", "Вариант 3"]
}
```

Fallback-парсер (`startsWith("{")` + `indexOf/lastIndexOf`) сохранён для совместимости со старыми моделями без поддержки схемы.

## 🚀 Быстрый старт (Quick Start)

### Требования
- **Node.js** >= 20.x
- **PostgreSQL** >= 14.x (локально или через облако Supabase / Neon)
- (Опционально) API-ключ **Google AI Studio** ([получить бесплатно](https://aistudio.google.com/))

### 1. Клонирование репозитория
```bash
git clone https://github.com/Le-Who/RPG_arena.git
cd RPG_arena
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Настройка переменных окружения
Скопируйте файл конфигурации:
```bash
cp .env.example .env
```

Отредактируйте `.env`, указав строку подключения к вашей базе данных PostgreSQL:
```env
DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5432/app_db"
```

### 4. Запуск сервера разработки
```bash
npm run dev
```

> **Миграции применяются автоматически.** При каждом старте сервера `instrumentation.ts` читает все `.sql` файлы из `drizzle/` и выполняет их идемпотентно (`CREATE TABLE/INDEX IF NOT EXISTS`). Ручной запуск `drizzle-kit push` нужен только при изменении `src/db/schema.ts` в процессе разработки.

Откройте в браузере: **`http://localhost:3000`**

### 5. Добавление API-ключей Gemini
1. Перейдите в раздел **`Настройки`** (`/settings`).
2. Вставьте один или несколько ключей Google AI Studio в поле добавления.
3. Выберите рекомендуемый профиль **«Баланс & Экономия»**.
4. Включите тумблер **«Live Gemini: ВКЛ»** (если ключи не добавлены, движок автоматически продолжит работу в автономном офлайн-режиме).

## 🖥️ Страницы и возможности интерфейса

- **Лобби кампаний (`/`)**:
  - Карточки 6 готовых миров с выбором архетипов (Следопыт, Клирик, Плут, Нетраннер, Самурай, Адвокат и др.).
  - Редактор создания своей свободной истории.
  - Виджет активности: счетчики дневных токенов и вызовов Flash/Lite.
- **Игровая комната (`/play/[id]`)**:
  - **Лог хроники**: кинематографичные ответы мастера, маркеры применённых моделей, плашки бросков кубика с результатом и DC.
  - **Панель действий**: 3 быстрых выбора (Flash-Lite) + поле авторского свободного ввода (Flash 3.8 + pre-roll d20).
  - **Инспектор героя**: статы, опыт, уровень, динамическая шкала HP, рюкзак и экипировка.
  - **Интерактивная SVG-карта**: координаты локаций, индикаторы опасности, туман войны и текущее положение героя.
  - **Вкладка Memory House**: просмотр всех 5 слоёв памяти в реальном времени с кнопкой принудительного сжатия.
- **Центр управления (`/settings`)**:
  - Пул маскированных ключей с ротацией.
  - Переключение 4 профилей роутинга.
  - Матрица кастомного назначения моделей на 4 типа задач.
  - Графический дашборд расхода суточных квот (прогресс-бары до 20/60/500 вызовов).
- **Архитектурный манифест (`/blueprint`)**:
  - Исчерпывающий интерактивный разбор направлений, механизмов, факторов и компромиссов проекта.

## 📡 REST API Справочник

| Метод | Эндпоинт | Назначение |
| :--- | :--- | :--- |
| `GET` | `/api/sessions` | Список последних 30 кампаний и их статусы |
| `POST` | `/api/sessions` | Создание новой кампании (пресет или кастомный мир) |
| `GET` | `/api/sessions/:id` | Полное состояние кампании (ходы, инвентарь, память, локации) |
| `DELETE` | `/api/sessions/:id` | Удаление кампании и связанных данных |
| `POST` | `/api/sessions/:id/act` | Совершение хода; `custom: true` — свободное действие с pre-roll d20 и responseSchema |
| `POST` | `/api/sessions/:id/compact` | Запуск компакции памяти через старшие Flash-модели |
| `GET` | `/api/sessions/:id/memories` | Статистика узлов памяти по 5 слоям и оценка токенов |
| `GET` | `/api/settings` | Текущие настройки роутинга, профили и маскированные ключи |
| `POST` | `/api/settings` | Обновление ключей, профилей и лимитов |
| `GET` | `/api/tokens/stats` | Агрегированная статистика токенов и вызовов за текущие сутки |
| `GET` | `/api/health` | Health-check эндпоинт (статус сервера) |

### Тело запроса `POST /api/sessions/:id/act`

```typescript
{
  action: string,  // текст действия (max 2000 символов)
  custom: boolean  // true = свободное действие (d20 pre-roll + responseSchema)
                   // false = выбор из 3 предложенных вариантов (нарративный режим)
}
```
