# Задержка хода: устройство и проверка

Ход включает получение актуального контекста, поиск памяти (иногда отдельный embedding-запрос), генерацию структурированного ответа, локальную проверку последствий и транзакцию PostgreSQL. После него раньше интерфейс дополнительно ждал полного снимка сцены. Поэтому время до доступного ответа не равно времени обычной короткой генерации Flash-Lite. Доля каждого этапа теперь измеряется; без реальных запросов к провайдеру нельзя приписать ему конкретные секунды.

## Что изменено

- NDJSON-поток передаёт текст по мере генерации. До полного ответа, проверки и фиксации транзакции он показан как формирующийся рассказ и не меняет игровой мир. Повторная попытка сбрасывает черновик.
- Подтверждённый ответ содержит героя, состояние мира, номер хода и варианты. Рассказ и следующий ввод доступны сразу после фиксации. Инвентарь и остальные панели обновляются фоном; устаревший снимок не откатывает новый ход. Выбор вещей временно недоступен до обновления их списка.
- Запись канонических фактов использует один lock/config-read на пакет и пакетную запись очереди embeddings. Последовательность применения фактов, provenance и атомарность сохранены.
- До трёх точных запросов предложенных действий получают embeddings в фоне. Кэш хранит только векторы, максимум 128 готовых записей на экземпляр процесса, TTL 2 минуты; результаты поиска каждый раз ранжируются по актуальной БД. Свободный текст использует обычный поиск. Подготовка имеет бюджет 5 секунд; ожидание уже начатой подготовки на критическом пути ограничено 750 мс.
- Извлечение дополнительных фактов, индексация памяти, подготовка вариантов и финальная запись метрик выполняются после ответа. Канонические последствия хода сохраняются до подтверждения. Долговечные задания памяти остаются в БД при сбое и доступны worker.
- При временной ошибке Gemini сначала пробуются другие ключи той же модели, затем повторяются временно неудачные ключи; лишь после этого допускается следующая модель. Общий deadline ограничивает попытки. Это не обещание повтора после исчерпания deadline.

Подготовка вариантов может расходовать embeddings на невыбранные действия. Она ограничена тремя вариантами, доступностью индекса и настройкой embeddings; кэш не общий для нескольких серверных процессов. Streaming не сокращает само вычисление модели, но позволяет читать раньше. Память, проверки и длина рассказа ради скорости не урезаны.

## Метрики

Успешный ответ и `game_turns.context_meta.timings` содержат `admissionMs`, `contextMs`, `retrievalMs`, `generationMs`, `validationMs`, `writesMs`, `serverMs`, а при наличии — `firstTextMs`, `attempts`, `thoughtTokens`, `cachedTokens`. `serverMs` включает завершение транзакции; `writesMs` заканчивается перед финальной записью результата в ledger. Полная телеметрия записывается в фоне. JSON-клиенты получают также `Server-Timing`; NDJSON-клиенты — метрики в событии подтверждения.

В браузере `performance.getEntriesByType('measure')` содержит `chronicle:turn:first-text`, `chronicle:turn:committed`, `chronicle:turn:paint`, `chronicle:turn:snapshot`. Сравнивать следует медиану и p95 для одинаковых модели, режима, размера контекста и типа действия; отдельно считать холодный/готовый embedding и повторы провайдера. Промпты и ключи в метрики не входят.

## Связанные исправления

«Добавить в действие» вставляет имя предмета; точный UUID передаётся скрытыми метаданными, проверяется по текущему инвентарю и участвует в защите повторов. Модель получает привязку без технического ID в тексте игрока.

Ответ модели поддерживает несколько открытых мест и явные маршруты за один ход. Переход соединяет исходное и конечное места, маршруты сохраняются в обе стороны. Простое упоминание не создаёт связь; скрытые места не отображаются. Старые открытия, существовавшие только в прозе, автоматически не восстанавливаются.

## Воспроизводимая проверка

Новых миграций нет. Для unit-проверок требуется `DATABASE_URL`; для интеграционных — отдельная мигрированная PostgreSQL, для браузерных — работающий сервер приложения.

```powershell
npm run typecheck
npm test
npm run lint
npm run build
$env:ARENA_ISOLATED_TEST_DB='1'
node --import tsx scripts/turn-latency-smoke.ts
$env:SMOKE_BASE_URL='http://localhost:3010'
node --import tsx scripts/turn-latency-browser.ts
```

`turn-latency-smoke` временно меняет настройки только явно выделенной тестовой БД и восстанавливает исходную строку; провайдер полностью подменён. Не запускать на рабочей БД. Браузерная проверка использует настоящий постепенно выдаваемый HTTP-поток с управляемыми задержками.

Проверено: 149 unit-тестов, TypeScript, ESLint, production build; интеграционные `smoke`, `v22-smoke` и `turn-latency-smoke` на PostgreSQL 18.4; браузерные сценарии потока, повторного ввода до обновления панелей, устаревшего снимка, восстановления зависшего потока, скрытого ID и карты. Реальный Gemini не вызывался: проценты ускорения и качество на реальном провайдере требуют отдельного замера.
