# Исследование памяти и узкая спецификация: источники после retrieval

Дата: 14 октября 2026. Исходный код: `27ed12b6d97722508284ea1ed9a81d55ccfe6ae6`.
Спецификация подготовлена до изменений production-кода. Предыдущие рекомендации исследованы заново и сопоставлены с текущими модулями и тестами; ниже самостоятельное техническое решение.

## Решение и основания

Реализовать только вариант C: передать исходные ходы найденных семантическим поиском узлов в уже существующий пакет свидетельств. Не вводить новую онтологию знания, версии persisted-фактов, новый verifier или дополнительные модельные вызовы.

В исходном `src/lib/turn.ts` сбор evidence находится на строках 242–250, а поиск выполняется на 260–286. Источники передаются только из `turnFrom/turnTo` 60 глобально ранжированных memories. Позднее найденные узлы могут находиться вне этих 60. `src/lib/narrative-evidence.ts` обрезает список referenced turns до 16; добавление retrieval в конец не исправляет потерю. SQL возвращает referenced строки хронологически, а snapshot оставляет лишь первые 32 000 символов: даже выбранный источник может исчезнуть при сериализации.

Это воспроизводимая граница доставки данных, не доказательство ошибки живого рассказчика. Источник всё ещё может быть недостаточным, неоднозначным или неверно прочитанным. Утверждение NPC остаётся утверждением; появление его текста в evidence не означает канонической истинности или принятия сообщения адресатом.

## Проверенные научные основания

- [LongMemEval, ICLR 2025, §§5.2 и 5.5](https://arxiv.org/html/2410.10813v2): сохранение исходных раундов и отдельная оценка чтения; сжатие может терять детали. Эксперименты об английском QA ассистента, не об открытой русской игре. Переносится требование проверять доставку источника, не численный выигрыш.
- [FEVER, NAACL 2018, §5.8](https://aclanthology.org/N18-1074.pdf): корректность ответа и полнота свидетельств оцениваются отдельно. Разбор 961 ошибочного предсказания не является частотой ошибок всего корпуса. Отсутствие источника не превращается в противоречие; новый разрешённый сюжет не обязан ранее встречаться в истории.
- [Breck и Cardie, COLING 2004, §§2–5](https://aclanthology.org/C04-1018.pdf): автоматическое построение иерархии на заранее размеченных выражениях, с ручной кореференцией источников. Из 535 английских новостных документов 66 использованы для разработки, остальные 469 для 10-fold CV; неоднозначные родительские связи допускаются. Таблица 3: 78,30% среднего по предложениям parent-link score, 54,52% полностью правильных структур на 2940 нетривиальных предложениях. Это не точность полного извлечения ролей, истинности или знания адресата. Ошибки возрастают при усложнении вложенности; выявление выражений и непосредственных источников оставлено дальнейшей работе. Поэтому автоматическая эпистемическая схема не обоснована этим результатом.

Дополнительно учитываются границы прежних исследований: FENICE — English-only; FactBank/MPQA дают согласие людей, не точность экстрактора; FANToM не доказывает универсального «не присутствовал — не знает»; NarCo/EntailmentBank различают поиск оснований и их соединение, не устанавливают причинность; CaTeRS не делает предотвращённое событие случившимся; Re3 и self-correction требуют оценивать порчу правильных ответов; Barkett/No Free Labels не подтверждают пользу JEV.

## Контракт изменения

1. Сначала выполняется существующий semantic retrieval при прежних условиях: `canUseLive`, embeddings enabled, Gemini keys и более шести loaded nodes. Изменять доступность поиска, k=8, ранжирование или provider не требуется.
2. После завершения поиска (включая пустой результат/ошибку) собирается один пакет evidence. Ранние agreement-history failure и разрешение хода остаются прежними.
3. Валидные `sourceTurn/turnTo` retrieved-узлов приоритетны перед прежними `turnFrom/turnTo` globally ranked nodes; дубликаты и несуществующие по номеру current/future/noninteger/nonpositive ссылки исключаются. Диапазоны между endpoint не разворачиваются.
4. Не более 16 referenced turns, 20 chosen turns, 40 source rows, 6000 символов на source и 32 000 символов общего source text. Приоритет retrieved-источников сохраняется в SQL output, прежде чем snapshot применит текстовый бюджет. Без retrieval порядок fallback SQL остаётся прежним.
5. Наличие ссылки не повышает authority: intention/legacy/disputed/verified определяются прежним кодом по исходному тексту, acceptedChanges и hash-bound audit. Оба role одного хода доступны, если помещаются в бюджет.
6. Известная потеря запрошенного источника (не найден, исключён лимитом или текстовым бюджетом) отражается существующим `truncated=true`. `completeHistory` всегда false. Это не обещание полноты role-пары, всех смысловых оснований или актуальных версий.
7. SQL остаётся параметризованным и session-scoped, с `turn_number < beforeTurn`; максимум две секунды evidence-query и прежний общий lease. Отказ загрузки остаётся best effort с неполнотой.
8. Генератор, guard, review/repair и сохранённый audit получают один и тот же snapshot. Не меняются генерация новых событий, правила, намерения, state reducers или атомарная публикация.

## Совместимость и риски

Нет новых persisted-полей, миграций, переписывания истории, изменения переносимого JSON, ID remapping, обновления существующих saves или API provider. Старые вызовы query/snapshot сохраняют допустимые defaults. Rollback — возврат двух production-модулей; данные не требуют обратной миграции.

Цена: та же одна SQL evidence-query теперь после retrieval, без увеличения лимитов/числа внешних вызовов. Изменённый состав текста может изменить реальные токены и вероятность достижения общего JEV лимита 100 000 UTF-8 bytes: лимит не ослабляется, успешность живой генерации не обещается. Приоритет одного источника может вытеснить другой; `truncated` — сигнал этого риска, не его устранение. Если sourceTurn указывает не тот ход или старую версию, доставка не исправляет первичную ошибку. Полные современные версии и intermediate sources остаются отдельной задачей.

## Baseline и критерии приёмки, до production-правок

Baseline: точный SHA выше; focused narrative evidence + real performTurn/PGlite suite **39/39**, no skip. Полный исходный ordinary suite: **824/824**, no skip (339,96 с локально), до production-изменений. Все провайдеры замещены, DB disposable, реальные credentials удалены стандартным test preload. Никаких живых моделей или production DB.

Новый RED-reproducer: более 60 memories, низкоранговый semantic hit с удалённым источником, не совпадающим с action lexical search; после поиска narrator prompt и verifier должны содержать исходный текст и player intent того хода. До изменения это assertion упало во всех шести сочетаниях режима/профиля; четыре fallback/guard-off controls прошли. Варианты free/preset × narrative/rules-light/d20, sourceTurn отличный от turnTo, отрицание/вложенное сообщение в исходном тексте, невозможность cross-session/future утечки. Отдельный тест заполненного source/text бюджета доказывает, что простой перенос блока без приоритета не решает проблему.

Negative controls: disabled/empty/failed retrieval сохраняет fallback; guard disabled не делает evidence-query; stale/hash-invalid audit не становится verified; отсутствующая ссылка остаётся неполнотой; budget не увеличивается; duplicate/current/future refs не занимают slots. Итоговые content/choices/state/job сверяются с принятым результатом, а не только с черновиком.

После GREEN проверяются focused tests, full ordinary suite, typecheck, lint, documentation checker, production build с unreachable synthetic DB и без секретов. Отдельное независимое read-only review и исправление замечаний до публикации PR. Native PostgreSQL/browser/live-model проверки сообщаются отдельно: если не запускались, не заявлять полный production readiness. Финальный SHA и remote bytes проверяются после публикации.

## Результат локальной проверки

Окончательный patch: focused **53/53** и полный ordinary suite **838/838**, без fail/cancel/skip (335,54 с локально). Добавлены три regression tests для лимитов/приоритета/неполноты и один настоящий performTurn integration с десятью дочерними случаями. `npm run typecheck`, `npm run lint`, `npm run check:docs` и `npm run build` прошли. Production build выполнен с пустым окружением, отключённой telemetry/auto-migrate и unreachable synthetic DB; внешние модели не вызывались.

Независимое read-only review проверило production diff, новые tests, raw RED/GREEN, исходный SHA и три основные научные ссылки. Блокирующих замечаний не найдено. Ограничение role-пары сохранено явно: наличие player-строки хода без narrator не обязано выставлять truncated; это индикатор известных пропусков номеров ходов и текста, а не сертификат достаточности. Исходный полный suite **824/824** выполнен до production-правок; проверка нового воспроизводимого дефекта на исходном коде действительно падала, а после исправления прошла.

Локальные native PostgreSQL, UI/browser и live-model оценки в этом изменении не запускались. PGlite выполнял настоящие SQL, pgvector retrieval и turn/commit path на синтетических данных; mocked provider/verifier не доказывают качество повествования. GitHub CI оценивается отдельно для опубликованного SHA. Нет merge, deployment, migration либо изменения реальных кампаний. Схема знания, качество моделей и универсальность всех миров остаются открытыми исследовательскими вопросами.
