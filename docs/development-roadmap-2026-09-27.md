# Приоритеты после интеграции 2.9

Дата: 27 сентября 2026. Реестр статусов — [основной roadmap](superpowers/plans/roadmap.md). [Стратегия 20 сентября](development-roadmap-2026-09-20.md) сохраняет прежние направления и ID. Этот документ уточняет ближайшие задачи; номера будущих релизов и сроки не назначаются.

## JEV-3 · P1 · важное направление: универсальное применение Jev

Уточнение после [живой оценки 2026-09-27](jev-narrative-evaluation-2026-09-27.md): 80 запросов первого этапа и ещё 48 диагностических запросов второго; [актуальная спецификация](narrative-research-synthesis-2026-09-27.md) уточняет дальнейшие применения. Score/Noul исследованы в отдельном прототипе, добавочной пользы относительно Choice пока не показали. Для JEV-3c приоритет — точная область вопроса и источник каждого утверждения; для JEV-3d — сравнение reranker с настоящим retrieval при равном контекстном бюджете. Не включать новые примитивы в игровой путь только ради наличия API. Разработанные контракты и условия внедрения находятся в отчёте; существующие ID задач сохранены.

Цель, прямо запрошенная владельцем проекта: сделать Jev переиспользуемым инструментом семантических решений для Chronicle, расширив применение за пределы существующего наблюдения за памятью и проверки повествования. Это приоритет ближайшего исследования и реализации после базовых измерений; автоматическое включение новых платных вызовов в каждый ход не предполагается.

Текущая база: `typesafe.ts`/`typesafe-pilot.ts` проверяют извлечённые факты в режиме наблюдения; `narrative-verifier.ts` и связанные policy/evidence/guard-модули выполняют узкие проверки повествования через TypeSafe/OpenRouter. Новая задача объединяет инфраструктуру без утраты разных политик этих потребителей. Существующий JEV-2 остаётся отдельным применением для ранжирования памяти.

| Срез | Что сделать | Критерий готовности |
|---|---|---|
| JEV-3a · P1 | Инвентаризация существующих клиентов, единый типизированный серверный контракт с ID задачи, версией вопроса/модели, кандидатами, разрешёнными источниками, сроком актуальности и политикой неопределённости; адаптеры над текущими транспортами | Оба существующих потребителя работают без изменения решений, прав, квот и поведения при отказах; replay записанных запросов и mock-контракты проходят |
| JEV-3b · P1 | Проверка предлагаемых механик 2.9: кто получил лечение/еду, подтверждает ли цитата конкретное время расписания, узнал ли именно этот NPC факт; различение выполненного действия, намерения, отрицания и рассказа о другом лице | Размеченный отложенный корпус по нескольким жанрам, включая ложные совпадения ревизии 2.9; сравнение с текущими эвристиками по каждому виду ошибок; сначала режим наблюдения |
| JEV-3c · P1 | Выбор существующей сущности и источника среди ограниченного списка; подтверждение ссылки, обнаружение противоречия с каноном, проверка доступности знания NPC | Никаких придуманных ID и межкампанийных источников; неоднозначность возвращает `insufficient`; происхождение каждого принятого вывода доступно для диагностики |
| JEV-3d · P2 | Ранжирование памяти (связь с JEV-2), маршрутизация multi-intent и выбор необходимой проверки, оценка соответствия предпочтениям рассказчика | Независимое сравнение с baseline; recall/precision, доля лишних проверок, ошибки границ, p50/p95 задержки и расход на ход; каждая функция включается отдельно |

Политика принятия решений принадлежит серверу. Модель не меняет числа ресурсов, ownership, инвентарь, канон или SQL напрямую. Вывод об отсутствии факта не превращается автоматически в отрицательный факт. `unsupported/insufficient`, низкая уверенность, таймаут и недоступность — отдельные состояния с явным поведением: сохранить прежнее состояние, отказаться от предложенного изменения либо применить существующую подтверждённую политику проверки. Нельзя молча превращать отказ провайдера в разрешение.

Для каждого применения нужны версия задания, ссылки на доказательства, оценка актуальности снимка, ограничение входа, таймаут, отмена, учёт usage и общий бюджет. Кэш привязан к owner/session, версии состояния, модели и формулировке задачи; проверка после repair использует окончательный текст. Пакетирование допускается только для независимых вопросов с совместимым контекстом. Диагностика не содержит ключей; подробные отчёты остаются за административной ролью без отмены ownership.

Порядок внедрения: корпус и воспроизводимый baseline → общий адаптер без изменения поведения → shadow-оценка 2–3 полезных задач → отдельное включение измеренных решений с возможностью отката. Пороги задаются по цене ложного принятия и ложного отказа, калибруются по задачам; одно значение confidence не является доказательством истины. Критерии перед активным включением: опубликованный отчёт с моделью, версией задания, разметкой, false accept/false reject, долей неопределённых ответов, p50/p95, токенами/стоимостью и проверкой изоляции. Преимущество над эвристиками пока является гипотезой.

При подготовке плана проверен официальный [индекс TypeSafe](https://docs.typesafe.ai/llms.txt): в нём перечислены Choice, Score, Noul и применения для маршрутизации, отбора доказательств и проверки цитат. Это варианты для исследования, не заявление об их наличии в нашем адаптере. Перед реализацией каждого примитива заново проверить текущий API, модель и ограничения по официальной документации и локальному [руководству интеграции](../.agents/skills/typesafeai-jev.md).

Первым исследовательским пакетом идут JEV-3a/3b, EVAL-3 и бюджет NARR-12. Дальнейшее расширение автоматики зависит от результатов этих измерений. Не вводить реестр reducers, морфологическую библиотеку, новую модель или дополнительные фоновые вызовы только потому, что они предложены в кандидатном roadmap.

## Уточнение после проверки научных работ

[Прикладная спецификация](narrative-research-synthesis-2026-09-27.md) отделяет подтверждённые методы от предположений внешних отчётов. Ближайшее исполнение — [план оценки конвейера](superpowers/plans/2026-09-27-grounded-narrative-evaluation.md) для JEV-3c/EVAL-2/3/QUAL-1, затем [план Score/Noul](superpowers/plans/2026-09-27-jev-primitive-experiments.md) для JEV-2/JEV-3d. Оба плана пока не выполнены.

Практический порядок: найти причину ошибки → сравнить решение на одинаковых данных → включить только измеренно полезное применение. Отдельно оцениваются финальный текст и принятые изменения, длинные траектории, правильность источников и художественные рубрики. Free-кампании не обязаны выполнять заранее заданный сюжет; нарушенное персонажем обещание не равно противоречию рассказчика канону. Новые вызовы Jev и production-политики этим исследованием не включаются.
