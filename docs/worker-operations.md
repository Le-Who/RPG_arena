# Memory worker — эксплуатация v2.5

Сверено с рабочим кодом 20 сентября 2026. Worker появился в v2.2; эта инструкция описывает текущую интеграцию. [README](../README.md) · [Roadmap](superpowers/plans/roadmap.md).

## Назначение

Процесс обслуживает durable `memory_jobs` и `memory_embeddings` в том же PostgreSQL, что и веб-приложение. Не ведёт игровые ходы, не создаёт произвольные факты без источника и не переносит память между кампаниями.

## Подготовка

1. Из корня проекта выполнить версионированные миграции `npm run migrate` (Node.js 24, PostgreSQL, настроенный `.env`).
2. Передать DATABASE_URL и серверный GEMINI_API_KEYS/GEMINI_API_KEY либо использовать ключи из ai_settings. Не публиковать их в логах или NEXT_PUBLIC-переменных.
3. В настройках включить нужные функции. Для semantic extraction нужны Live + extraction; для embeddings — ключ и embeddingsEnabled.
4. Проверить один проход: `npm run worker -- --once`.
5. Запустить `npm run worker` под supervisor/systemd/контейнерным оркестратором, с restart policy и отдельным пользователем без избыточных прав. Рабочая директория — корень проекта; `.env` и база должны соответствовать веб-приложению. Готовой конфигурации постоянного сервиса в репозитории нет.

Ключи из текущей БД ещё не зашифрованы. Для production сначала реализуйте key-at-rest encryption и авторизацию пространства; само вынесение worker не решает эти задачи.

## Поведение

- На tick: не более одного semantic-задания и пачка до 32 embeddings одной выбранной кампании. Вызовы провайдера идут вне транзакции удержания задания.
- Пауза 15 секунд между tick; нет busy-loop при пустой очереди.
- Semantic lease: 60 секунд, запрос к Gemini: не более 15 секунд на цепочку. Включённый пилот Jev добавляет не более 5 секунд на HTTP-запрос без повтора; его ошибка не отменяет успешное извлечение.
- Embedding lease: 45 секунд, сетевой budget: 15 секунд по умолчанию.
- Попытка увеличивается при claim. После трёх неудач задание становится failed.
- Backoff увеличивается экспоненциально; смена lease token делает поздний ответ непригодным для записи.
- SIGTERM/SIGINT дают закончить текущую bounded-задачу, затем heartbeat становится stopped.
- Потерянный процесс оставит processing до истечения lease. Следующий worker подхватит задачу либо переведёт её в failed при исчерпанных попытках.
- Для нескольких workers соблюдаются SKIP LOCKED/аренда/CAS; при этом project quotas и глобальный concurrency budget пока не атомарны, поэтому не увеличивайте число workers без оценки лимитов.

## Пилот Jev

Миграция `0004` добавляет настройки TypeSafe и nullable JSON-отчёт задания. После нормализации проверяется до шести фактов на `jev-1.13.0`; действие игрока обозначено как намерение. Существующие проверки цитат, provenance, приоритетов и lease сохраняются. Отчёт записывается вместе с завершением задания под тем же lease. Пилот выключен по умолчанию, ранжирование и автоматическое отбрасывание фактов не включены.

Включение, masked key/source, тест подключения и отчёты доступны в «Настройки → Для разработки». `TYPESAFE_API_KEY` имеет приоритет над БД. Сервис worker должен получать ту же переменную, что и веб-сервер. Подробности: [эксплуатация нового этапа](story-experience-operations.md). Для корректной работы timestamp-очередей PostgreSQL должен использовать timezone UTC.

## Диагностика

Откройте `/system` или `GET /api/system/status`. Ответ содержит счётчики semantic/embedding-очередей, последние semantic-задания, несовместимые embedding spaces, heartbeat и последний отчёт worker. `queues.oldestPendingAt` относится к embeddings в состояниях pending/processing, а не ко всем заданиям памяти. Online означает heartbeat моложе двух минут при статусе, отличном от stopped; это не подтверждение успешности последнего вызова Gemini.

- **Нет ключа:** очереди ждут; это не потеря состояния.
- **Worker не запущен:** deploy сервиса нужен отдельно. `after()` и ручной проход работают как вспомогательные пути.
- **Failed:** устранить причину провайдера, затем «Повторить ошибки». `POST /api/system/process` с `{ "action": "retry" }` возвращает failed semantic/embedding-задания всего пространства в pending и сбрасывает попытки. Готовые задания не сбрасываются.
- **Сменили размерность:** reindex выбранной кампании на `/memory`. Векторы старой размерности не используются новым поиском.
- **Задание processing без worker:** дождаться окончания lease и запустить следующий tick. Не записывать ready вручную.
- **Растёт backlog:** проверить квоты, latency, сбои сети и источник нагрузки; настроить alerts на возраст oldest pending, failed ratio и исчезновение heartbeat.

`POST /api/system/process` с `{ "action": "process" }` выполняет один ограниченный проход. Это ручной инструмент приватного приложения, а не уже настроенный планировщик. Перед открытым развёртыванием защитите его авторизацией/roles, как и остальные API.

## Проверка эксплуатации

На отдельной тестовой БД без ключей запуск `--once` должен вывести отчёт `paused: true`, завершиться и записать heartbeat `stopped`. Это проверка пути запуска и доступа к БД, а не извлечения или индексации. При включённых функциях и доступном ключе отчёт содержит `extracted`, `indexed`, `failed`, `processed`, `elapsedMs` и `paused`.

Контрактные проверки запускаются через `npm test`, интеграция очередей с тестовым провайдером — через `npm run smoke:v22` при работающем тестовом сервере. Для приёмки постоянного сервиса отдельно проверьте restart, просроченный lease, retry после отказа и исчезновение heartbeat. Записывайте среду и результат прогона: mock-provider не измеряет реальную пропускную способность, качество или стоимость Gemini.
