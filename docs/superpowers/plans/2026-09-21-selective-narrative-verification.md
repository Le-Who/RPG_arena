# Selective narrative verification implementation plan

**Goal:** Prevent consequential narrative/state and historical-claim contradictions with selective Jev checks, preserving a fast path for descriptive prose and original evidence for historical assertions.

**Architecture:** Evidence-backed turn resolution, deterministic check selection, metadata-first generation, buffered consequential prose, one batched Jev verification per guarded draft, bounded repair and fail-closed critical checks. Facts/agreements retain provenance; derived memory cannot establish its own historical authority.

**Spec:** `docs/narrative-consistency-research-2026-09-20.md` plus the user's approved selective-checking refinement in conversation.

**Tech stack:** Next.js 16.3.5, TypeScript, PostgreSQL/Drizzle, Gemini structured generation, Jev `jev-1.13.0` Choice API.

## Constraints and pitfalls

- No production campaign correction, deploy or push as part of this implementation without a new applicable instruction. Preserve user roadmap/docs and `.agents/`.
- Use each player's credentials only; the shadow pilot toggle is not authorization to silently change gameplay behavior. Expose separate verification configuration and explicit missing-key behavior.
- An existing memory citation proves neither entailment nor truth; retain versioned source excerpts, role and time. Player intentions and NPC claims are not automatically events.
- Metadata declarations and lexical detectors are fallible. Report residual risk on the unchecked path; do not claim that all hallucinations are prevented.
- Never publish a buffered critical draft on timeout, missing credentials or invalid verifier response. Unknown and contradictory are distinct.
- No reroll or application of operations twice during repair. No DB transaction held while waiting for providers. Preserve lease fencing, idempotency, failure rollback, owner isolation and offline mode.
- Questions have fixed templates, unique IDs and bounded inputs. Check missing operations in prose as well as explicitly proposed ones. Independent questions can batch; dependent stages cannot pretend to run in parallel.
- User prefers OpenRouter credentials: support explicit `openrouter` provider via `https://openrouter.ai/api/alpha/decisions`, `typesafe/jev-1.13`, and direct TypeSafe separately. Never forward one provider's key to another or redirect authorization. Local live harness reads `OPENROUTER_API_KEY`; production uses owner-scoped stored configuration.
- A late guard can hold only unseen text; already displayed text cannot be retroactively protected. Track emitted prefix; do not silently replace it with contradictory repaired text.
- Source retrieval is bounded and session-scoped; truncation/missing context is explicit. No arbitrary facts assumed false merely because search missed them.
