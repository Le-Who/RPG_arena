## 2. Цель продукта и состояние main

Это не полная реализация D&D, а универсальная интерактивная новелла: игрок задаёт намерение; модель предлагает прозу и структурированные последствия; сервер валидирует и применяет состояние. Профиль d20 — только одна из механик. Preset и free различаются явно: пресет допускает авторский процедурный fallback, свободная история требует AI.

В исходном roadmap почти все эти возможности ещё планировались, но в загруженном main уже существовали:

- preset/free и d20/rules-light/narrative;
- runtime-парсер resolution и reducers предметов, локаций, целей, NPC, окружения;
- транзакция хода с advisory-lock и уникальным requestId;
- слои памяти, provenance, semantic extraction, embeddings и hybrid rerank;
- REST API, шесть пресетов, настройки и квоты.

Поэтому заново реализовывать v2 было бы ошибкой. Этап v2.1 сохраняет исходный движок и усиливает его узкие места.

### Существенные находки в исходном коде

| Узел | Фактическая проблема | Решение v2.1 |
|---|---|---|
| `turn.ts / performTurn` | Снимок и reducers вычислялись до advisory-lock; после блокировки версия не проверялась. Два разных requestId могли сохранить одинаковый номер хода и перезаписать ресурсы. | Внутри блокировки повторно читаются turnCount и status. Устаревший снимок отклоняется до любой записи. Совпадающий requestId получает replay. |
| `engine.ts` | Оркестратор бросал кости, а offline engine делал новый бросок. Текст мог описывать один исход, сохранённые dice — другой. | В engine передаётся `resolvedDice`. Тот же бросок определяет прозу и эффекты. Остальная вариативность пресета теперь воспроизводится seeded PRNG от действия/мира/хода/броска. |
| Создание сессии | Сессия, пролог, предметы, память и карта сохранялись отдельными запросами. | Одна Drizzle-транзакция, включая стартовую outbox. |
| Стартовая карта | В нескольких пресетах `startLocation` и имя первого узла отличались. | Текущий первый узел получает канонический `startLocation`. |
| Free intro | Общие openingChoices использовались и для free. | У свободной истории нет выдуманных стартовых вариантов, первый ход задаёт игрок. |
| `embeddings.ts` | Стабильная и preview-модели считались одним семейством; cosine молча обрезал несовпадающие размерности. | Только стабильная `gemini-embedding-2`, точное совпадение модели/размерности, проверка длины, finite/nonzero и явный отказ при несовместимости. |
| Индексация | Обработчики могли одновременно выбирать pending-строки; запоздавший ответ записывался по одному id, без проверки версии контента. | Атомарная краткая аренда, `leaseToken`, lease expiry, content-hash CAS, retries с задержкой. Вызов провайдера вне транзакции. |
| Надёжность outbox | Постановка происходила только в `after()`: процесс мог завершиться после commit, но до создания задания. | Memory node и pending embedding записываются в одной транзакции. `after()` теперь лишь доставляет уже сохранённую работу. |
| Семантические факты | Достаточно было совпадения первых 40 символов цитаты; намерение игрока могло считаться доказательством. NaN проходил проверки confidence. | Полная цитата должна быть в ответе рассказчика; намерение — не факт; типы и finite confidence проверяются. |
| Канон | Поздний extractor мог заменить более новый факт или понизить state/seed до ai-semantic. | Запрет отката sourceTurn и замены state/seed семантическим извлечением/компакцией. |
| Дедлайны Gemini | Таймаут применялся на каждую пару модель × ключ, цепочка могла длиться многократно дольше. | Общий deadline всей цепочки; ошибки провайдера не возвращают его raw body. |
| Зависимости | Аудит Next 16.2.6 показал high/critical advisories. | Next + eslint-config-next обновлены до 16.3.5, PostCSS и baseline mapping обновлены. Production audit: 0 advisories на момент проверки. |

## 3. Что добавлено для пользователя

- Новый адаптивный центр историй: общий sidebar, поиск по пространству, статусы реального AI-подключения, краткое руководство.
- Библиотека с жанровым и механическим фильтрами, поиском и избранным в PostgreSQL.
- Два новых полноценных пресета: **Станция «Эхо»** (научная фантастика, narrative) и **Последний рейс** (современный детектив, rules-light). Всего восемь.
- Выбор героя пресета и двухэтапный конструктор собственного мира. Никаких навязанных фэнтезийных ролей в свободном режиме.
- Кампании: переименование, архив/восстановление, подтверждаемое удаление, продолжение с сохранённого состояния.
- Новая игровая комната: варианты, свободное действие, requestId для безопасного повтора, состояние предметов/целей/мира, чипы принятых и отклонённых изменений, режим чтения, подгрузка ранних ходов.
- Страницы персонажей, памяти и журнала; текстовый фильтр честно отделён от семантического поиска.
- Полный экспорт журнала в Markdown.
- Настройки моделей, размерности, extraction, лимитов; тест подключения делает настоящий `embedContent`, не имитацию успешного соединения.
- Доступные диалоги: Escape, focus trap и возврат фокуса. Иконки имеют подписи, состояния загрузки/ошибок видны, reduced-motion учитывается.
- Локальные иллюстрации и шрифт с кириллицей; внешние CDN не нужны для рендера интерфейса.

## 4. Контракт gemini-embedding-2

**Модель зафиксирована:** `gemini-embedding-2`. Preview и `gemini-embedding-001` не используются как скрытые fallback.

- Endpoint: `v1beta/models/gemini-embedding-2:embedContent`; для отдельных документов в пачке — `:batchEmbedContents` с массивом отдельных requests.
- Ключ передаётся сервером в `x-goog-api-key`.
- `task_type` / `taskType` не передаются: модель 2 их не поддерживает.
- Запрос: `task: search result | query: …`.
- Документ: `title: … | text: …`.
- По умолчанию **768 измерений**, в UI доступны 768/1536/3072. Модель поддерживает 128–3072 и сама нормализует усечённые векторы; cosine дополнительно проверяет корректность входа.
- Модель имеет общий лимит 8192 входных токенов; приложение использует более консервативные ограничения текста по символам, не выдавая их за точный tokenizer.
- Queue-state: pending → processing(lease) → ready; transient error → pending с backoff; после трёх неудач → failed. Истёкшая lease доступна для повторной обработки.
- Чтение фильтрует **обе таблицы по sessionId**, exact model/dims, ready status и соответствие content hash актуальному тексту.
- Hybrid rerank: semantic similarity, importance, recency, salience, provenance; есть ограничение числа нод на слой.
- Query-vector cache: до 128 записей, TTL 2 минуты; ключ включает сессию, модель, размерность и текст запроса. Результаты retrieval не кешируются: они видят текущее состояние таблиц.
- При изменении размерности/версии требуется reindex. Старые векторы не сравниваются с новыми.

**Не обещается:** реальное качество recall@K без evaluation. Интеграционный тест использует явно обозначенный mock-provider для проверки транспорта и состояния, а не для имитации семантической точности. В окружении проверки не было Gemini API-ключа; live quality/latency требуют отдельного прогона с настоящим провайдером.

## 5. Следующие этапы — технические варианты

### P0 — безопасное размещение и гарантии ресурсов

1. **Владельцы и авторизация.** OIDC/Auth.js или self-hosted identity provider. `ownerId` у сессии, составные ограничения, все API от verified identity; PostgreSQL RLS как дополнительный барьер. Сейчас приложение — private single-owner workspace, не публичный SaaS.
2. **Ключи.** Envelope encryption AES-256-GCM с KMS/Vault, rotation и key-id; секрет никогда не возвращается клиенту, в логах только fingerprint. Сейчас сохранённые ключи в БД не зашифрованы. Возможность держать их только в серверном окружении уже есть.
3. **Квоты и admission control.** Сейчас read-count → call не является атомарной резервацией. Ввести provider/project budget ledger и резерв в транзакции, корректировать по usageMetadata. Несколько ключей одного Google-проекта не считать независимыми квотами. Дневные счётчики лучше считать в заданной timezone, не в локальной timezone процесса.
4. **Принятие хода до AI.** CAS защищает данные, но конкурирующие запросы могут оплатить две генерации. Следующий шаг — short lease на turn job до вызова модели; revision + inputHash + requestId + status + result. Транзакцию нельзя держать открытой во время сети.
5. **Полная валидация API.** Единые request/response schemas, размер потока тела, same-origin/auth protection на каждой mutation, rate limits и key-test budget. Текущий proxy — базовая проверка UUID, content-length и cross-site Fetch Metadata, не замена авторизации.

### P1 — скорость и эксплуатация

1. **Постоянный worker.** Существующую PostgreSQL outbox обслуживать отдельным процессом/pg-boss: lease heartbeat, jitter, dead-letter, ручной replay, backlog age и oldest-pending alert. `after()` остаётся fast path, но не единственным способом доставки.
2. **pgvector.** При подтверждённом росте количества фактов добавить `vector(768)` и HNSW, запросы с фильтром tenant/session. `real[] + cosine` остаётся fallback. Для разных размерностей — отдельные versioned index spaces; cutover только после backfill и проверки recall. Не считать ANN автоматически быстрее на маленькой сессии.
3. **Контекст и кеш.** Параллельно загружать профиль/состояние/память; кешировать immutable canon и profile prompts; relevance-select inventory с гарантированным inclusion явно используемого itemId; budget по точным токенам, а не только символам. Не кешировать изменяемый мир без revision.
4. **Streaming.** SSE/Web Streams для статуса и художественной части; финальное состояние показывать только после commit. Пользователь должен видеть, где ещё предложение модели, а где подтверждённый результат.
5. **Наблюдаемость.** OpenTelemetry trace одного хода: admission → DB → retrieval → generation → validation → commit → indexing. p50/p95, стоимость успешного хода, доля schema repair, rejected ops, stale responses, queue age. Никаких полных секретов/приватного контекста в логах.
6. **Пагинация и backup.** Dashboard сейчас ограничен 100 кампаниями, snapshot — 80 ходами/нодами; есть older-turn pagination и полный Markdown export. Следующие задачи — cursor pagination библиотек, point-in-time backup, JSON import/export с schemaVersion и безопасным remapping ID.

### P2 — качество, богатство и расширяемость

1. **Evaluation MEM-2g.** Размеченный набор минимум 100 query/relevant-memory pairs по жанрам; hard negatives из других кампаний; recall@5/@8, precision, latency и token cost. Сравнить vector-only / hybrid / MMR. Не фиксировать threshold без измерений.
2. **Нарративный канон.** Отделить намерение, наблюдение, гипотезу NPC и подтверждённый факт. Ввести fact revisions, validity interval, contradiction links и явную процедуру разрешения противоречий. Полная цитата подтверждает источник, но сама по себе не доказывает логическое следование — нужен entailment-check/evaluation.
3. **Авторские story packs.** Версионированная спецификация жанра, правил, допустимых эффектов, NPC, локаций, сцен, предметов и ограничений. Preset offline engine должен двигаться к authored scene graph, а не бесконечным общим beats.
4. **Расширяемые механики.** Типизированный registry профилей и компонентов панели. Нынешний CharacterState всё ещё сохраняет числовые поля ради совместимости с v1, хотя narrative UI/prompts их не используют. Следующий рефакторинг — discriminated union common/resources без обязательных HP/XP/gold.
5. **Мультимодальный канон.** `gemini-embedding-2` позволяет индексировать изображения, аудио, видео, PDF. Предлагаемый ingestion: MIME/размер allowlist → malware scan → immutable blob → provenance → отдельная multimodal Content entry → versioned vector. Текстовый task prefix не переносить механически в мультимодальный input. Для PDF учитывать ограничения страниц/8192 tokens и делать чанки с page provenance.
6. **Ветвление и checkpoint.** Append-only события + периодические snapshot, branch-from-turn, replay reducers. Не копировать просто последний JSON мира: иначе ветка наследует будущее и неверную память.
7. **Долгосрочные цели и отношения.** Quest dependencies, NPC agendas и scene clocks; модели разрешены только операции из контракта профиля. UI показывает, почему изменилось отношение или появился срок.

## 6. Проверка и критерии готовности

- **52 unit-теста:** исходные reducers/parser/dice; 36 сочетаний жанр × профиль × режим; vectors; полная цитата; приоритет канона; общий серверный бросок и воспроизводимость offline flavor.
- **`scripts/smoke.ts`:** 8 транзакционных созданий; consistent locations; durable outbox; 6 конкурентных действий; идемпотентный replay; archive/restore/rename/export; free AI_REQUIRED; mock-provider leases/CAS и изоляция сессии. Созданные тестовые кампании удаляются.
- **`scripts/migrations-check.ts`:** отдельная пустая PostgreSQL-база; обе миграции; чтение новой схемы; повтор без новых ledger entries; удаление тестовой БД.
- **`scripts/browser-smoke.ts`:** desktop 1440 и mobile 390; navigation/filter/favorites; focus/guide; preset/custom creation; offline turn; inventory/memory; AI-required UI; settings и отсутствие page errors/горизонтального overflow.
- Типогенерация Next, TypeScript без emit, production build и управляемый запуск с `/api/health` выполняются в финальной проверке.
- `npm audit --omit=dev`: 0 vulnerabilities на момент проверки. У dev-инструментов остаются отдельные advisories; этот результат не является полным security audit приложения.

## 7. Границы этого этапа

Не реализованы auth/multi-tenancy, encryption at rest, pgvector, постоянный worker, атомарное резервирование provider quota, реальная embedding quality evaluation, streaming, импорт внешнего мультимодального корпуса или ветвление кампаний. Юридические решения не подменяются техническим анализом. Неиспользуемые обещания не выдаются за готовые функции.
