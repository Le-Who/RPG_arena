## 2. Принятые решения (и альтернативы)

### 2.1 «Модель предлагает — сервер решает»
Единый JSON-контракт для обоих типов хода (`RESOLUTION_RESPONSE_SCHEMA`), runtime-нормализация (`parseResolution`) и чистые reducers (`applyResolution`) с лимитами по профилю. Provider `responseSchema` остаётся подсказкой провайдеру, а не источником доверия.
*Альтернатива:* zod-схемы. Отвергнуто ради нулевых зависимостей и полного контроля клампов; при росте контракта — мигрировать на zod с теми же тестами.

### 2.2 Профили механик как спецификация (`src/lib/profiles.ts`)
`d20` (серверный d20 vs DC), `rules-light` (оценка риска + 2d6: полный успех / успех с ценой / провал), `narrative` (без бросков и счётчиков). Профиль задаёт ресурсы, лимиты, тип проверки, UI-панели и текст канона для промптов; модель не может его изменить.
Пресеты объявляют профиль сами: Гербарий и Трибунал — rules-light, Глашатай — narrative, остальные — d20.

### 2.3 Транзакция + идемпотентность
`pg_advisory_xact_lock(hashtext(sessionId))` сериализует ходы кампании; `requestId` + уникальный индекс `(session_id, request_id)`; повтор возвращает сохранённый результат (`stateChanges` хранится в narrator-ходе). Один ход = один `turnNumber` для player и narrator.

### 2.4 Память: provenance вместо эвристики
`source` (`seed | state | ai-semantic | compaction | heuristic`), `sourceTurn`, `contentHash`, `entityKey`, `confidence`, `evidence`. Каноническая память пишется reducers в транзакции (`upsert` по entityKey для эволюционирующих фактов, `append` по хешу для событий). AI-экстрактор — отдельная schema-constrained задача на `fastTaskModel`, асинхронная (`after()`), идемпотентная по ходу, принимает факт только при наличии дословной цитаты в тексте и `confidence ≥ 0.55`, и не извлекает то, что уже есть в состоянии (ресурсы, предметы, локации, квесты).

### 2.5 Эмбеддинги: `gemini-embedding-2` без обязательного pgvector
Ограничение среды: в sandbox нет расширения `vector`. Решение — переносимое хранилище `memory_embeddings.vector real[]` + cosine в приложении. Поиск всегда в пределах `sessionId` (сотни нод → миллисекунды), поэтому отсутствие ANN-индекса не критично.
Особенности модели учтены по документации: `task_type` не поддерживается — используются префиксы `task: search result | query: …` и `title: … | text: …`; `outputDimensionality` 768 (MRL, авто-нормализация); батч через `batchEmbedContents`; алиасы `gemini-embedding-2` / `-preview`.
Hybrid-rerank: `0.55·sim + 0.2·importance + 0.1·recency + 0.05·salience + 0.1·provenance`, порог сходства, ≤4 ноды на слой, результат исключается из общего дайджеста (нет дублей), retrievedIds пишутся в `contextMeta` хода.
*Путь апгрейда:* `CREATE EXTENSION vector`, колонка `vector(768)`, HNSW, замена ранжирования на `<=>` — интерфейс `searchMemory()` сохраняется.
*Альтернативы рассмотрены:* Gemini File Search (managed RAG) — отвергнут: нет session-scoped фильтрации и provenance; внешний vector DB (Qdrant/pgvector-cloud) — избыточно для per-session объёмов.

### 2.6 Лимиты и ключи
`enforceLimits`: перед вызовом считаются сегодняшние вызовы по модели, исчерпанные пропускаются (лимит × число ключей). Ключи из БД объединяются с `GEMINI_API_KEYS` из окружения. Запрет включить Live без ключей; при удалении всех ключей Live гаснет автоматически.

### 2.7 Миграции
drizzle migrator с ledger `__drizzle_migrations`; SQL написан идемпотентно (IF NOT EXISTS, ADD COLUMN IF NOT EXISTS, guarded FK), проверен двойным применением и апгрейдом поверх v1-таблиц. `MIGRATIONS_STRICT=1` — падать при ошибке.

## 3. Что изменилось для игрока
- Свободная история: выбор механики, свои статы/навыки/черты/предметы, стартовая точка, эпоха, фракции; никаких фэнтезийных дефолтов.
- Любой ход меняет мир: цели, персонажи, предметы, объекты сцены, состояния героя, локации — и всё показано чипами «что изменилось» под текстом мастера, включая то, что сервер отклонил.
- Панели «Цели» (квесты + NPC с отношением), «Мир» (карта + объекты сцены), «Память» (provenance, семантический поиск, переиндексация).
- Кнопка «использовать» у предмета — свободное действие с проверкой владения на сервере.
- Свободная кампания без ИИ говорит об этом прямо и даёт кнопку «повторить ход».

## 4. Дальше (не вошло в этот релиз)
1. **Шифрование ключей в БД** (AES-256-GCM, секрет из окружения) — сейчас ключи хранятся открытым текстом, как и раньше; для production обязательно.
2. **Матрица регрессий «жанр × профиль × режим»** (ARCH-1g) — фикстуры промптов и golden-тесты парсера на реальных ответах моделей.
3. **Eval-набор памяти** (MEM-2g): recall@K по размеченным вопросам к кампании, метрики стоимости/задержки; A/B «с retrieval / без».
4. **Стриминг нарратива**: JSON-контракт стримится плохо; вариант — двухфазный ответ (сначала narration text/stream, затем компактный stateChanges-вызов) либо частичный парсинг JSON-стрима.
5. **pgvector-провайдер** за флагом окружения (см. 2.5).
6. **Пагинация лога** (cursor по turnNumber) и экспорт кампании (JSON/Markdown).
7. **Многопользовательность/аутентификация**: сейчас настройки и кампании глобальны.
8. **Ретраи фоновых задач**: `after()` выполняется в процессе; для устойчивости — таблица jobs + cron/route-триггер.
9. **Лицензия** (LEGAL-1) — решение владельца.
