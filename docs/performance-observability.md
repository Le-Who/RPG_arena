# Наблюдаемость производительности

Административная страница `/system` показывает агрегаты Web Vitals, тайминги браузера и сохранённых ходов, а также размер первичного запроса генерации. `/api/system/performance` защищён `withAdminAccess`: обычный профиль не получает агрегаты. Публичного чтения отдельных ходов эта возможность не добавляет.

## Включение и границы сбора

Браузерная телеметрия выключена по умолчанию. Значение включения задаётся до сборки и запуска сервера: статически собранный layout зависит от build-окружения. `CHRONICLE_TELEMETRY_ENABLED=1` включает reporter в серверном layout и приём `/api/telemetry/vitals`. В development reporter не отправляет данные. Учитываются Do Not Track и Global Privacy Control. Для работы хранилища нужна миграция `0018_performance_samples.sql`.

До сетевой отправки URL превращается в разрешённый шаблон, например `/play/[id]`; сервер повторяет нормализацию. В таблице нет IP, account/owner/session ID, текста истории, промпта, ключей провайдеров или произвольного URL. Передаются имя метрики, числовое значение, шаблон маршрута, грубый класс размера экрана и разрешённый тип навигации. Произвольные поля тела не сохраняются. POST остаётся под общей проверкой origin, но не создаёт гостевую identity.

Тело ограничено 8192 байтами, пакет — 20 замерами. Значения конечны, неотрицательны и ограничены; названия проверяются по собственным свойствам allowlist. Сервер сам определяет rating. Отправка best-effort, без повторов. В каждом процессе работает локальный token bucket, не более одной записи одновременно; при занятом пуле замеры отбрасываются. Короткая транзакция с неблокирующей advisory-блокировкой ограничивает общий приём 600 замерами в минуту между процессами. Таймаут отдельного SQL statement — 1 секунда.

После приёма сохраняется не более 20 000 последних строк. Очистка строк старше 14 дней выполняется при следующем допущенном приёме; без новых записей физическое удаление откладывается, но отчёт всегда исключает устаревшие строки. Это ограниченная диагностическая выборка, а не полный или случайный учёт посещений.

## Что означают числа

- Web Vitals относятся к жизненному циклу документа. Поздний callback не приписывается текущей SPA-странице: используется исходный navigation URL. Стабильный callback предотвращает повторную отправку при React render.
- Тайминги первого экрана — первый завершённый Resource Timing для соответствующего API в документе. Они включают клиентскую сетевую задержку; это не только серверное время.
- `Server-Timing: app;desc="response-ready"` измеряет интервал от начала identity wrapper до готового Response, включая admission и cleanup. Для streaming Response он не включает окончание потока.
- Отчёт браузера показывает до 20 000 последних замеров за 1–14 дней. Серверная часть — до 500 последних narrator turns за 30 дней. Малые выборки помечены. p50/p75/p95 в отчёте вычисляются линейной интерполяцией.
- Бюджет промпта хранит только числа. System/user — длина первичного собранного запроса в кодовых единицах UTF-16; schema — длина JSON. Значения ограничены 5 000 000. Токены оценены по правилу `ceil(chars / 3.6)` для каждой части и не равны usage провайдера.
- Retry, repair и отдельные запросы проверки не входят в этот бюджет. Секции измеряются по переданным фрагментам: они могут пересекаться, не покрывают весь промпт и не обязаны складываться в общий размер. Процент — медиана долей по отдельным ходам, а не отношение независимых медиан. Offline-ход без запроса не получает искусственный бюджет.
- Старые turns без `promptBudget` поддерживаются. Строгий portable JSON разрешает известные bounded поля бюджета и отвергает неизвестные секции.

## Локальная проверка

Focused unit/PGlite проверки: `tests/performance-report.test.ts`, `tests/performance-store.test.ts`, `tests/performance-portable.test.ts`, `tests/server-timing.test.ts`. Они используют общий изолированный test-environment и не обращаются к рабочей БД или провайдерам.

`node --import tsx scripts/performance-panel-browser.ts` собирает реальный React-компонент во временный loopback HTTP fixture с синтетическими ответами API, проверяет Chromium desktop/mobile, отсутствие горизонтального overflow страницы, keyboard selector и таблицы, loading/error состояния. Артефакты: `output/playwright/performance/`. Скрипт не обходит auth в приложении и не подключается к БД. Это проверка UI и агрегирования, а не подтверждение репрезентативности реальных production-замеров.
