Реестр содержит **228 файлов src**: 119 библиотек, 39 файлов каталога components (38 TS/TSX компонентов/хуков и 1 CSS), 43 API route и 27 остальных DB/framework/page/layout/metadata/CSS файлов. Отдельно перечислены **132 ordinary test files, 10 opt-in PostgreSQL integration files, 8 helpers, 3 JSON fixtures** и 111 файлов scripts/deploy/migrations/CI/public/configuration. Каждый путь src/tests присутствует ровно один раз. Базовый аудит до исправлений имел 103 ordinary test files, 519 статических вызовов test и 596 runtime registrations. Текущий AST насчитывает757вызовов; loops и nested subtests разворачивают один вызов в несколько registrations. Это разные единицы, ни одна не равна числу assertions. Свежий исходный run18.10 имеет1032registrations; шесть уже существовавших JSON/Jev cases отделены от85 добавленных этим этапом. В реестр дополнительно внесён прежний `resolution-json-envelope.test.ts`; новые файлы этого этапа — только checkpoint/transfer/rotation. Итоговый current-source gate и исторические runs приведены ниже.

Mapper использует TypeScript AST: static import, re-export, require и **literal dynamic import**, включая импорты внутри test callback. `import type` и named imports, состоящие только из `type` элементов, исключены из runtime рёбер и сохранены отдельно. Относительные пути и `@/*` разрешаются в существующие файлы; directory import разрешается в index.ts. Неразрешённых local imports нет. Два nonliteral dynamic imports относятся к сгенерированным isolated test bundles; они не превращаются в статические runtime edges, их исполнение подтверждается отдельными native fixtures. Обратные consumers и достижимость из page/layout/route/proxy/instrumentation перечислены отдельно от operational scripts. Ни direct import, ни indirect reachability не доказывают исполнение функции или assertion её поведения.

Для каждого test file JSON хранит actual test names/lines, класс, источник чтений, exact runtime/type-only imports, domain evidence, relevance/objectivity notes и текущие исправленные regressions. Для каждого src file — line count/kind, exact direct runtime test references и отдельную indirect graph reachability, consumers, production entrypoints и browser associations. Type-only `typesafe-report.ts`, CSS и статические public assets имеют N/A для runtime unit; отдельный тест на каждый файл не требуется. SQL, прочитанный и выполненный в genuine disposable PGlite, считается SQL behavior evidence; `assert.match` текста SQL — только дополнительный structural guard.

Browser associations основаны на полном UI/API review и явных imports в inline React bundles либо владельце проверяемого UI flow. Так, PerformancePanel и VisualGallery имеют собственные bundled fixtures, а composer/map/settings flows принадлежат соответствующим компонентам приложения. Наличие общего browser script в домене не превращает весь компонент и каждый API route в выполненное покрытие. JSON сохраняет точный scenario scope; mocked API обходят настоящий handler/SQL. Определение и чтение сценария отделены от результата его запуска: окончательные browser logs добавляет координатор.

Источники карты — domain audits `output/test-audit/story-state.json`, `storage-identity.json`, `providers-evaluations.json`, `ui-api.json`; статус исправлений уточнён по Task 2/3/4 reports, `task-2-4-review.md`, `task-3-ui-review.md` и root UI-fixture report. Generated output хранится локально и не является опубликованной частью docs; JSON содержит идентификаторы групп и буквальные evidence excerpts. Некоторые baseline gaps уже закрыты: они сохранены как исторические observations, а `fixedRegressions` имеет приоритет при оценке текущего backlog.

Follow-up evidence прочитано из `output/test-followup/cli-report.md`, `native-report.md`, raw native TAP/run/cleanup JSON, npm audit JSON и трёх fresh standalone Chromium result JSON; общий результат и границы изложены в [ограниченном follow-up](../test-followup-2026-10-09.md). `drizzle-kit` удалён как неиспользуемый; три существующих browser scripts используют явно объявленный direct dev `esbuild@0.28.2`. Это ограниченный dependency результат, не общее заключение о безопасности.

Unit LCOV записывается в `output/test-coverage.lcov`; статус конкретного run приведён ниже. Probe и полный LCOV получены Node/V8 поверх tsx и содержат transformed helper functions (`__export` и другие). Поэтому raw V8 line/function/branch counters допустимы только с указанием instrumentation и loaded subset; **они не являются точными original TypeScript line/branch percentages и процентом всего приложения**. Для отсутствующих в LCOV файлов следует писать «not loaded», не выдумывать execution или accuracy. Browser React, Next entrypoints и opt-in native PostgreSQL требуют своего evidence.

Исключены из активного execution denominator node_modules (third-party), generated `.next`, `revisions`/revision candidates (включая tsconfig exclusions), output и `.env*`. Первоначальный root browser runner использовал только **имена переменных** из `.env` для очистки environment: значения не использовались и не печатались. Новый runner задаёт explicit environment allowlist; mapper не читает `.env` values. Операционные script definitions, deployment manifests, immutable migrations/ledger и public metadata перечислены, но наличие пути не доказывает deployed execution. Mapper не выполнял full suite/build, live providers, рабочую БД или unskipped native PostgreSQL.

## Пофайловое чтение карты

Для конкретного файла найти `sourceModules[].path` и сравнить `directRuntimeTestImports` с `indirectRuntimeTestReachability`, затем `testFiles[].testCases/objectivity` и `evidenceGroups` по `auditGroupIds`. Прямой dynamic import route handler внутри test также отражён; отсутствие static top-level import не означает отсутствия handler evidence. `browserEvidenceScripts` — только scoped ownership association, её execution status читается отдельно. Для SQL/deploy/public/scripts использовать `ancillaryFiles`; inventory path и definition не равны успешному execution.

Legacy `src/lib/world-map.ts` имеет только test consumer `experience-v25.test.ts`; `src/lib/jev-mechanics.ts` тоже не достижим из текущих production entrypoints и имеет только test consumer. `parseTypeSafeResponse` — legacy export внутри live `typesafe.ts`: actual verifyTypeSafeFacts использует Jev response parser. Они отмечены как relevance gaps, без требования писать ещё mirror tests к неиспользуемой логике.

Численные raw counters, финальные unit/native/browser results и ссылки на их logs могут быть обновлены только после соответствующего запуска. Данная карта сохраняет inspected baseline, существующие regressions и конкретные будущие сценарии раздельно.
