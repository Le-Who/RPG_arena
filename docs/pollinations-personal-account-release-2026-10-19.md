# Личный аккаунт Pollinations — проверка и поставка 19 октября 2026

[Контракт и настройка](text-providers-operations.md) · [Roadmap](superpowers/plans/roadmap.md) · [Предыдущие production-замеры БД](database-cold-entry-production-2026-10-19.md).

## Область

В поставку включены ранее подготовленные изменения личного Pollinations после проверки контрактов, хранения, расходов и фактических React-компонентов. Исходный незавершённый набор сохранён перед интеграцией; исправления регионов/пула БД остаются в истории отдельными коммитами.

Личное подключение общее для рассказчика и личных изображений. Для изображений владелец явно выбирает аккаунт оплаты и модель. Галерея показывает плательщика и модель до создания, а у каждой записи сохраняются собственные источник, модель и seed. Отказ личного ключа не переключает расходы на аккаунт приложения. После передачи кампании готовые изображения доступны без новой генерации, но незавершённые личные изображения прежнего владельца не расходуют чужой ключ.

Добавлена только миграция `0020_personal_pollinations_visuals`: два поля настроек и источник оплаты в `scene_visuals`, с прежним значением `application` по умолчанию. Исторические SQL и записи ledger не изменены. Campaign exports, copies и forks не переносят профильные ключи или визуальные записи. Ротация уже существующего зашифрованного Pollinations key сохраняет новые настройки.

## Исправления при проверке готовности

- Публичный HTTPS client metadata позволяет начать штатное подключение без предварительного ручного ключа и выбранной модели. Trusted origin и callback обязаны совпадать; публичный документ не создаёт гостя и не обращается к БД.
- OAuth запрашивает только `generate` и категории `text,image`; доступ к истории расходов не требуется. Discovery и обмен кода имеют полные дедлайны, включая адаптеры, игнорирующие AbortSignal.
- Успех, отмена и ошибка возвращают в настройки с фиксированным русским сообщением. Отмена/ошибка сохраняют прежний ключ; raw error, code и key не переносятся в URL. Уведомление закрывается клавиатурой с возвратом фокуса, в том числе пока настройки ещё загружаются.
- Каталог проверяет текущие разрешения ключа перед использованием кэша, разделяет владельцев/отпечатки ключей и повторно проверяет идентичность перед выдачей. Старые ответы подключения и каталога не меняют новую форму после смены ключа.
- Чтение настроек изображений сокращено с четырёх SQL до двух; сохранение с шести до трёх. Сохранение возвращает канонический UPDATE RETURNING; повторное чтение чужих разделов не требуется.
- Общий счётчик правок теперь включает синхронные пользовательские изменения всех вложенных разделов. Если рассказчик изменён во время позднего сохранения иллюстраций, «Сохранить и вернуться» оставляет новую правку открытой.
- Кнопки подключения переносятся на 320 px; состояние загрузки, ошибка проверки доступности, отсутствие серверной конфигурации и повтор явно различимы. Названия платных моделей и источник расхода объясняются рядом с выбором.

## Проверки

Локальная среда: Node 22.23.2, синтетические provider credentials, loopback DSN; PGlite используется только в одноразовых fixtures. Тяжёлые проверки выполнялись последовательно из-за ограниченного Windows commit memory.

Браузерные fixtures фактических компонентов: Pollinations settings **63**, сохранение черновиков **26**, галерея **13**; 1280/390/320 px, клавиатура, отсутствие горизонтального переполнения и ошибок страницы. Подтверждён RED→GREEN для закрытия формы с новой правкой и переноса длинной кнопки на 320 px. Галерея подключает реальные стили sidebar, а не приближение fixture.

Локально прошли **66/66** проверок в 15 затронутых файлах: OAuth/каталоги/настройки, secrets, populated legacy replay, image handler/render/quota/model. Дополнительно **2/2** новые actual-handler регрессии подтвердили RED→GREEN при отзыве account session сразу после SQL чтения/записи рассказчика: ответ 401 без старых настроек, запись остаётся у исходного владельца, служебный допуск очищается.

Полный ESLint и production Next 16.4.2 Turbopack build с TypeScript прошли. Checker документации проверил 101 файл и 425 локальных ссылок, команды и ledger. CI и production smoke фиксируются после завершения поставки.

## Границы

Живой OAuth consent с личным кошельком, списание Pollen и качество изображений/структурированных ответов не проверялись и не следуют из mock-тестов. Production smoke не создаёт кампании и не вызывает генерацию; проверяет отдельный технический профиль, настройки, публичную конфигурацию входа и старт авторизации до внешнего consent. Полная оценка качества моделей остаётся задачами VIS-0/NARR-11.
