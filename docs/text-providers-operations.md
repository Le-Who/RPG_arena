# Провайдеры рассказчика

Состояние реализации: 19 октября 2026. [README](../README.md) · [Roadmap](superpowers/plans/roadmap.md).

## Настройка

В «Настройки → Рассказчик» выберите Gemini напрямую, OpenRouter или Pollinations. Для Pollinations нажмите «Подключить аккаунт Pollinations»: вход, создание ключа, бюджет и срок подтверждаются на стороне провайдера. Модель можно выбрать после подключения из списка либо ввести ID вручную. Для OpenRouter сохраните собственный API-ключ и ID модели; подсказки публичного каталога сохранены. Доступность каталога не гарантирует доступ к модели по вашему тарифу и поддержку требуемой JSON-схемы. При отказе модели приложение показывает ошибку, не ослабляет проверку состояния.

Выбор принадлежит профилю владельца и применяется к его кампаниям. Это пока не индивидуальное назначение модели каждой кампании. Ключ OpenRouter рассказчика отделён от ключа OpenRouter для Jev. Личное подключение Pollinations общее для рассказчика и личных иллюстраций; общий серверный ключ Pollinations используется только при явном выборе аккаунта приложения для изображений.

Через выбранного провайдера выполняются narration/resolution, review/repair, автозаполнение новой истории, компакция и семантическое извлечение. Для внешнего провайдера используется одна явно выбранная модель; Gemini сохраняет прежние профили роутинга, а его автозаполнение — Flash Lite. Настройки моделей Gemini относятся к прямому Gemini, не к ID внешних каталогов.

Эмбеддинги по-прежнему использует `gemini-embedding-2` с отдельными прямыми Gemini-ключами. Без них внешний рассказчик работает, семантические текстовые задачи доступны, но векторная индексация/поиск не становятся автоматически доступны. Сохранённые факты и исходная история сохраняются.

## Pollinations: подключение кошелька

Основной путь — кнопка «Подключить аккаунт Pollinations». Модель и API-ключ до входа не требуются. Если модель ещё не выбрана, сохраняется Pollinations с выключенным живым рассказчиком. После возврата выберите модель, включите рассказчика и сохраните настройки. Ручной ID модели и ручной API-ключ находятся в раскрывающихся дополнительных настройках.

Для публичного HTTPS-развёртывания достаточно корректного серверного `CHRONICLE_PUBLIC_ORIGIN`. Приложение публикует `GET /api/settings/pollinations/client` — штатный OAuth Client ID Metadata Document с названием Chronicle Engine и точным callback URI. Pollinations получает его без гостевой идентичности и доступа к БД. Этот URL должен быть доступен провайдеру по HTTPS без авторизации и редиректов. Механизм подтверждён текущим [исходным кодом Pollinations](https://github.com/pollinations/pollinations/blob/main/enter.pollinations.ai/src/services/client-metadata.ts) и OAuth discovery; реальный consent отдельно не выполнялся.

Существующий вариант с зарегистрированным App Key имеет приоритет и нужен для локального HTTP-входа. Оператор регистрирует точный callback URI и задаёт серверу:

```dotenv
POLLINATIONS_APP_KEY=pk_your_registered_app
POLLINATIONS_REDIRECT_URI=https://your-domain.example/api/settings/pollinations/callback
```

Если задан `CHRONICLE_PUBLIC_ORIGIN`, callback по умолчанию строится из него; явно заданный callback должен иметь тот же origin, чтобы браузер вернул cookie подключения. Локальная разработка допускает HTTP localhost/127.0.0.1 с App Key; для обычного домена требуется HTTPS. Без публичного HTTPS origin и без App Key вход недоступен; ручной ключ остаётся дополнительным вариантом. Общий web/worker keyring обязателен для безопасного хранения.

Используется authorization code + PKCE S256. Краткоживущая HttpOnly-cookie зашифрована и привязана к владельцу, state и конфигурации. Обмен кода и хранение полученного `sk_` выполняются сервером. Callback прикрепляет ключ и необязательный срок действия, не включает платные вызовы автоматически. Ответ без `expires_in` поддерживается; некорректное явно переданное значение отклоняется.

Discovery ограничен 8 секундами, весь обмен кода вместе с повторным discovery — 10 секундами; отмена ограничивает ожидание также при зависшем fetch-адаптере. После успешного подключения, отмены у провайдера или ошибки обмена браузер возвращается на настроенный адрес `/settings` с фиксированным результатом `connected`, `cancelled` или `failed`. Коды авторизации, ключи и текст ошибок провайдера не переносятся в адрес возврата. Отмена и ошибка сохраняют прежний ключ. Если конфигурация не задаёт доверенный адрес возврата, callback отвечает 400 без перенаправления.

Запрашиваются категории моделей `text,image`, scope `generate`, начальный бюджет 5 Pollen и срок 7 дней. Чтение метаданных самого ключа и каталогов не требует доступа к балансу, истории расходов или управлению аккаунтом: Chronicle не запрашивает `usage`, `profile`, `keys` и `machines`. Это соответствует текущему [контракту разрешений Pollinations](https://github.com/pollinations/pollinations/blob/main/shared/auth/authorize-config.ts). Пользователь меняет и подтверждает разрешения у Pollinations. Бюджет ключа — ограничение расходов из кошелька, а не отдельный баланс. Просроченный ключ требует повторного подключения; refresh token не выдаётся. Удаление ключа в Chronicle прекращает его использование для рассказчика и личных иллюстраций; для отзыва на стороне провайдера используйте кабинет Pollinations. Chronicle не включает наценку разработчика; для зарегистрированного App Key её политика задаётся в Pollinations.

Контракт сверялся с [официальным Connect User Wallets](https://github.com/pollinations/pollinations/blob/main/BRING_YOUR_OWN_POLLEN.md). Реальный consent требует действия пользователя; mock-тесты его не заменяют.

## Личные иллюстрации и каталоги Pollinations

В настройках появился отдельный раздел «Иллюстрации Pollinations», доступный также при рассказчике Gemini/OpenRouter. Владелец явно выбирает «Мой аккаунт Pollinations» или «Аккаунт приложения Pollinations». Для личного аккаунта сохраняется отдельная модель; модель общего аккаунта выбирает администратор. В галерее до кнопок генерации показаны аккаунт оплаты и модель; каждая запись также показывает свой источник. Ошибка личного ключа не переключает запрос на общий ключ.

Миграция `0020_personal_pollinations_visuals` добавляет настройки профиля и `scene_visuals.account_source`. У прежних настроек и иллюстраций источник по умолчанию `application`. Созданная иллюстрация сохраняет источник, модель и seed; последующие изменения настроек их не меняют. При переносе гостевой кампании без личных настроек её ожидающие/ошибочные личные иллюстрации блокируются: новый владелец создаёт новую запись со своим аккаунтом. Ранее готовые байты читаются без нового расхода. Иллюстрации и ключи по-прежнему не включаются в portable JSON и forks.

Каталоги текста и изображений загружаются автоматически при открытии соответствующего выбора и по кнопке обновления. Сервер проверяет модальности, категорию и поддерживаемый endpoint; использует канонический ID. Для подключённого аккаунта запрос каталога авторизован и включает доступные ему приватные модели. Текущие разрешения ключа проверяются через `/account/key` при каждом чтении: учитываются категории/ID/aliases и ограничение Quest Pollen для paid-only моделей. Доступ по фактическому балансу и успешный структурированный ответ этим не гарантируются; неизвестная поддержка JSON-схемы не объявляется подтверждённой.

Метаданные кэшируются в процессе на 15 минут, максимум 128 каталогов; персональная область включает владельца и отпечаток ключа. Параллельные запросы одной области разделяют загрузку. Успешный предыдущий каталог можно показать при ошибке обновления не старше 24 часов с датой проверки и явным предупреждением. Ошибка проверки самого ключа не выдаёт старые персональные данные. Ключи и сырые ошибки провайдера не возвращаются в браузер. Ручной ID остаётся доступен при недоступном каталоге; окончательный отказ провайдера отображается явно.

## Хранение, расходы и ошибки

Перед запуском применить `npm run migrate`: миграция `0016_text_provider_settings.sql` добавляет настройки с Gemini по умолчанию, зашифрованные ключи и срок Pollinations. Настроить общий web/worker keyring по [руководству](secret-storage-operations.md). Исторические миграции не изменяются. Rotation и перенос старого профиля учитывают новые секреты; API отдаёт только признаки наличия ключей.

Попытки внешних провайдеров учитываются раздельно как `openrouter:<model>` и `pollinations:<model>`. Локальный дневной предел каждой внешней модели использует существующее поле Flash; число Gemini-ключей его не умножает. Это предел HTTP-попыток, не денежный лимит. У провайдера остаются собственные баланс, тарифы и ограничения. Повтор временной ошибки — максимум один, та же модель, новая резервация квоты.

Внешний рассказчик не переключается на Gemini или другую модель приложения. При ошибке, исчерпании локального лимита или истёкшем подключении включённого внешнего рассказчика ход не сохраняется, включая preset. Явное выключение Live сохраняет возможность процедурного preset. Внутреннюю маршрутизацию шлюза Pollinations нельзя приравнять к гарантии конкретного upstream; у OpenRouter приложение запрещает provider fallback.

Структурированный JSON и стрим проходят существующие parser/guard/reducer/lease/atomic commit. Указание JSON schema провайдеру само по себе не означает принятие результата сервером. Пакеты SSE, оборванный поток, ошибка провайдера, отмена и лимит ответа проверяются транспортом. Ключи и сырые ответы ошибок не включаются в диагностику.

Для external transport лимит assembled SSE frame учитывает newline между data-строками. Wire bytes считаются также для ignored fields; ограничения content/frame/wire проверяются отдельно. Исключение synchronous start/text callback или sync/async telemetry callback заканчивает попытку безопасным CALLBACK_ERROR и не вызывает новый provider request. Уже переданная successful telemetry не переотправляется как ошибка провайдера. Это не расширяет обработку async void callbacks или deadline зависшего callback. [Локальные регрессии и границы](p2-boundary-test-coverage-2026-10-15.md).

Публичный каталог разделяет незавершённый fetch между одновременными вызовами одного provider, возвращает отдельные копии записей и сохраняет успешный результат на 60 секунд с момента завершения загрузки. На точной границе TTL выполняется новая загрузка; ошибка не отравляет pending/cache и позволяет немедленный повтор. Кэш остаётся внутри процесса и не гарантирует upstream доступность.

## API

- `GET/POST /api/settings/text-provider`: чтение безопасного представления и изменение настройки текущего владельца.
- `GET/POST /api/settings`: общая настройка также возвращает `textProvider`, `textModel`, `canUseLive` и, при наличии, `textKeyExpiresAt`. Интерфейс использует серверную готовность выбранного рассказчика; наличие Gemini-ключей не требуется для внешнего провайдера.
- `GET /api/settings/text-provider/models?provider=openrouter|pollinations`: публичный текстовый каталог с кратким кэшем; неизвестная поддержка schema не выдаётся за подтверждённую.
- `GET /api/settings/pollinations/client`: публичный OAuth client metadata document.
- `GET /api/settings/pollinations/connect`: доступность OAuth-конфигурации.
- `POST /api/settings/pollinations/connect`: начало consent, возвращает URL.
- `GET /api/settings/pollinations/callback`: owner/state-bound обмен одноразового кода.
- `GET /api/settings/pollinations/models?kind=text|image&refresh=1`: каталог с текущими разрешениями личного ключа; без `refresh` используется TTL.
- `GET/POST /api/settings/visual-provider`: безопасное чтение и сохранение личного выбора аккаунта и модели иллюстраций.

## Проверка и границы

Поздний ответ сохранения общих настроек сохраняет новые правки, внесённые после отправки: canonical значения принимаются только для полей, которые пользователь с тех пор не менял. Новый введённый ключ остаётся в форме. Если такие правки появились во время «Сохранить и вернуться», форма остаётся открытой с сообщением, что отправленный вариант сохранён, а новые изменения ещё ожидают сохранения. Ошибки503/409 настройки рассказчика также оставляют draft/key для повтора. Actual handler round trip и отдельные Chromium fixtures описаны в [локальном отчёте](p2-ui-persistence-test-coverage-2026-10-15.md); synthetic browser API не заменяют проверку production handler.

Общий transport deadline Gemini распространяется также на чтение JSON/SSE и callbacks; read/cancel, игнорирующий AbortSignal, не удерживает application promise бесконечно. Explicit usage `0` сохраняется, unknown usage не выдаётся за достоверный ноль. Ошибки и terminal telemetry используют безопасные коды. Нулевые персональные Flash/Lite/embedding limits сохраняются через settings API и прекращают новые вызовы до fetch; это допустимый запрет расхода, а не автоматический minimum 1. [Текущие регрессии и ограничения](test-coverage-audit-2026-10-09.md).

Контрактные тесты используют синтетические ответы, integration — одноразовую PGlite. После отдельного разрешения владельца 27 сентября выполнены три живых синтетических генерации через `gemini-3.5-flash-lite` и один запрос `gemini-embedding-2`. Все три ответа разобраны по схеме; потоковая сборка совпала с итоговым текстом; эмбеддинг содержит 768 конечных чисел. БД и реальные кампании не использовались. Повторяемый сценарий: [eval-gemini-provider-smoke.ts](../scripts/eval-gemini-provider-smoke.ts), запуск `node --env-file=.env.eval --import tsx scripts/eval-gemini-provider-smoke.ts --live`. Без `--live` запросы не выполняются.

Это проверка транспорта, а не оценка качества полного игрового хода: используются короткие синтетические инструкции вместо полного контекста кампании. В сцене неудачного открытия сундука модель сохранила закрытое состояние, но дополнительно предложила `danger=2`; в сцене кристаллов добавила объект. Успешный разбор JSON не доказывает обоснованность таких предложений. Их допустимость определяют серверные проверки полного хода; для вывода о качестве нужна отдельная оценка принятых изменений и финального повествования по [исследовательскому плану](superpowers/plans/2026-09-27-grounded-narrative-evaluation.md).

OpenRouter и Pollinations проверены на синтетических контрактных и интеграционных ответах, без живой генерации; OAuth consent — без настоящего кошелька. Качество конкретной модели и фактическая поддержка схемы остаются предметом отдельных контролируемых запусков. Сведения о поставке доработки личного аккаунта 19 октября приведены в отдельном [отчёте проверки](pollinations-personal-account-release-2026-10-19.md).

Проверка исходного этапа 27 сентября: полный `npm test` — 525/525; после дополнений отдельно проверены 30 тестов интеграции ходов и 3 теста готовности интерфейса. `npm run typecheck`, `npm run lint`, `npm run build` и `npm run check:docs` прошли. Браузерные проверки с подменой API покрыли desktop/mobile, клавиатуру, сохранение настроек, ошибки каталога, внешнего рассказчика без Gemini и истёкший Pollinations. Реальные публичные каталоги вернули 458 текстовых моделей OpenRouter и 187 Pollinations на момент проверки; это не статический список поддерживаемых моделей. Миграция в пользовательской БД не выполнялась.


Проверка доработки 19 октября выполняется на Node 22.23.2 локально и 22.23.3 в CI. Контрактные тесты проверяют дедлайны OAuth, отмену/ошибку без потери прежнего ключа, окончательную проверку идентичности, разграничение каталогов, источник расходов и совместимость миграции. Браузерные проверки фактических React-компонентов с синтетическими HTTP-ответами: [Pollinations settings](../scripts/pollinations-settings-browser.ts) — 63 проверки на 1280/390/320 px; [галерея](../scripts/visual-gallery-browser.ts) — 13; [сохранение черновиков](../scripts/settings-draft-p2-browser.ts) — 26. Новая правка рассказчика во время сохранения иллюстраций не закрывает окно «Сохранить и вернуться».

Mock consent, API fixtures и чтение публичных каталогов не подтверждают живое подключение кошелька, расход Pollen или качество генерации. Конкретные команды, результаты CI, миграция и production-проверки фиксируются в [отчёте поставки](pollinations-personal-account-release-2026-10-19.md).

## Независимые сервисы и стоимость — 19.10.2026

В настройках появились две независимые задачи: «Рассказчик» и «Иллюстрации». Рассказчик поддерживает прямой Gemini, OpenRouter и Pollinations; изображения — Pollinations и личный OpenRouter. Новые профили начинают с выключенными иллюстрациями. Миграция `0021_independent_visual_providers` сохраняет прежнее поведение существующих профилей и записей.

«Подключённые сервисы» сохраняет один основной ключ на сервис, не меняя выбранные задачи, модели или предпочтение Live. OpenRouter и Pollinations используют одно подключение для текста и картинок. Дополнительные ключи Gemini и отдельная проверка повествования остаются в дополнительных настройках. Удаление общего ключа явно предупреждает о влиянии на обе задачи; другой аккаунт не подставляется.

Короткий список содержит до трёх подходящих официальных моделей. Текущий выбор сохраняется в пределах этого лимита, даже если найден поиском. Модели сообщества отмечены и доступны в полном каталоге с разрешениями ключа; прежний выбор не заменяется молча. Неподтверждённая генерация без исходника не рекомендуется как основной вариант. Известные модели только для редактирования и SVG-only вывод исключаются также при серверной проверке; ручной ID не обходит запрет.

Цены сохраняют валюту, единицы, дополнительные сборы и варианты. Пример текста — 8000 входных и 1000 выходных токенов без кэша и инструментов, не полный игровой ход. За изображение показывается фиксированная полная цена либо исходная ставка/оценка с условиями. Неизвестная стоимость не равна нулю. Сравниваются только сопоставимые цены; качество истории не выводится из дешевизны. Подробности тарифа, дата, источник и ответы на частые вопросы доступны через кнопку справки. Gemini использует датированную официальную таблицу, потому что Model API не отдаёт цены.

Каталоги загружаются при открытии выбора и не блокируют bootstrap или обычное сохранение. OpenRouter проверяет ограниченный короткий список и выбранную модель; сохранённый endpoint определяет и показываемую ставку, и маршрут запроса. Отсутствующий маршрут не заменяется ценой другого. Сохранённые fallback-цены помечаются как устаревшие; они не подтверждают разрешения ключа.

OpenRouter использует non-streaming POST `/api/v1/images`, один результат, зафиксированный endpoint и растровый формат, без fallback маршрута. JSON/base64 и байты изображения ограничены, произвольные URL из ответа не загружаются. Повторы сохраняют provider/model/payer/endpoint/outputFormat/seed/размеры. После ожидания каталога или чужой lease сервер повторно проверяет сессию, владельца и текущий ключ перед попыткой; перед выдачей байтов проверяется доступ к чтению.

Переход во внешний вход Pollinations не сохраняет роли автоматически. Если есть открытые правки настроек, сначала нужно явно сохранить или отменить их; ручное подключение ключа остаётся независимым от этих правок. Это сохраняет черновик при внешнем переходе и не применяет выбранную модель до подтверждения.
