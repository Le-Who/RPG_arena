# Сравнение и интеграция `revisions/2.8-revision`

Дата: 27 сентября 2026. Источник — локальный снимок проекта в `revisions/2.8-revision`, а не готовый патч. После нормализации CRLF/LF содержательные отличия сосредоточены в четырёх новых подсистемах и их интеграции. Исторические файлы, миграции `0000–0015`, Drizzle journal, конфигурация развёртывания и большинство тестов совпадают и не переносились повторно. Исходную папку не изменяли.

| Предложение | Решение | Причина и адаптация |
|---|---|---|
| Отложенные события и цели NPC | Принято с изменением контракта | Дают миру память о будущих событиях. Исходный reducer объявлял событие произошедшим сразу после передачи в промпт, даже если рассказчик его пропустил. Теперь `due` остаётся открытым до явного `complete` с цитатой из итогового рассказа. Назначение, отмена и цель NPC также требуют цитату после возможной правки рассказа. Время предложений считается от начала хода; пересечённое за ход событие можно завершить сразу. Неизвестный NPC отклоняется, неоднозначное имя не выбирается произвольно, а одноимённые события в разное время не схлопываются. |
| Голос рассказчика | Принято как предпочтения кампании | Пять шкал и ограниченный ввод полезны для разных жанров; значения по умолчанию не добавляют блок голоса. Соблюдение стиля и границ не доказано unit-тестами, поэтому документация не называет их гарантией. |
| Механические состояния | Принято с исправлением правил | Модификаторы делают проверки последовательнее. Исходная версия штрафовала физическим ранением социальную 2d6-проверку и автоматически снимала голод/усталость без еды/отдыха. Теперь 2d6 учитывает область действия, включая флирт, допрос и обвинение; устойчивые состояния требуют события сцены. Истечение таймера обновляет семантическую память; конвейер памяти сохраняет последнюю версию семантического факта даже в насыщенном ходе. Отрицание и ложное совпадение «пожар» не активируют правило. |
| «Ранее в истории» и эпилог | Принято с уточнением достоверности | Детерминированная сводка помогает вернуться в кампанию. Чтение разных таблиц объединено в repeatable-read транзакцию; главы выбираются отдельно от эпизодов, а строки Markdown нормализуются. Источником остаётся сохранённая память, которая может содержать устаревшие сведения. |
| Совместимость JSON | Исправлено сверх поставки | Новый `world_state` заявлялся переносимым, но строгий валидатор JSON не принимал эти поля; он также пропускал поля жизни мира и applied changes из 2.7. Добавлен ограниченный allowlist для обоих этапов и регрессионные тесты на round-trip и некорректный таймер. |
| Следующий roadmap из поставки | Переработан | Предложение переиспользовало `WORLD-4` для перемещения NPC, хотя в действующем roadmap этот ID означает развитие карты. Свободный текст распорядка недостаточен для детерминированного определения присутствия; автоматические штрафы отношения за «пропуск» встречи преждевременны. Эти задачи оставлены с явными предварительными условиями и без смены существующих ID. |

Стадия 2.8 закрывает вертикальные срезы `WORLD-2/3`, `MECH-4`, `NARR-9/10` и часть `UX-2`, а не исходные большие направления целиком. Знания NPC, история взаимодействий, проверяемые автономные реакции, завершённый UX финала и оценка на живом провайдере остаются открытыми. Подробнее о принятых контрактах — в [описании этапа](world-agenda-and-narrator.md).

Проверка локальной интеграции: `npm test` — 429 тестов без ошибок; `npm run typecheck`, `npm run lint`, `npm run build` и `npm run check:docs` — успешно (45 документов и 109 локальных ссылок). Реальные вызовы AI, миграция производственной БД и браузерный аудит этим отчётом не заявляются.
