# Автозаполнение и наблюдение за памятью

Срез реализации: 20 сентября 2026. [README](../README.md) · [Roadmap](superpowers/plans/roadmap.md).

## Развёртывание

Выполните `npm run migrate` перед запуском веб-сервера и worker. Миграция `0004_typesafe_pilot.sql` добавляет поля настроек и nullable отчёт semantic-задания, сохраняя старые кампании. PostgreSQL должен использовать timezone `UTC`: текущие очереди хранят UTC в timestamp без зоны.

Для автозаполнения нужны включённый живой мастер и ключ Gemini. Вызов `POST /api/story-drafts/autofill` принимает `{draft}`, где `draft` содержит строки `title`, `worldName`, `pitch`, `era`, `tone`, `mainQuest`, `startLocation`, `name`, `archetype`, `backstory`, `skills`, `startItems` и `rulesProfile`. Списки передаются строками через запятую. Ответ `{patch, modelUsed}` содержит только пустовавшие текстовые поля. Кампания не записывается. Пустой/пробельный текст считается незаполненным; непустые значения не переписываются. Некорректные длины/списки отклоняются, а не обрезаются.

Модель фиксирована на `gemini-3.5-flash-lite` независимо от игрового routing profile. Единственный исправляющий запрос после невалидного JSON остаётся на Lite, в общем бюджете 30 секунд. Расход — `creation`, `sessionId:null`. Ошибка квоты не включает fallback на Flash. Отмена или изменение формы исключает применение устаревшего результата.

## TypeSafe / Jev

Ключ теневого пилота задаётся в «Настройки → Для разработки» и принадлежит профилю. `TYPESAFE_API_KEY` не подставляется этому пилоту автоматически: переменная используется отдельными CLI-evaluation, которые явно её поддерживают. GET возвращает только маску и источник. Персональные ключи в БД защищены серверным keyring и привязаны к профилю. Developer-инструменты и shadow pilot предназначены только для администрации; независимая проверка повествования — другая функция со своим явно настроенным административным fallback.

Пилот выключен по умолчанию. Включённый worker отправляет одним запросом до шести нормализованных фактов с цитатами, повествованием и явно обозначенным намерением игрока. Фиксированная модель `jev-1.13.0` возвращает типизированные `supports`, `contradicts`, `unsupported`, confidence и вероятности. Это наблюдения модели, а не установленная истина.

HTTP-бюджет — 5 секунд, без повторов. Тайм-аут, отказ, невалидный ответ и ошибки диагностики не меняют сохранение фактов. Отчёт хранит модель, версию инструкции, факты/цитаты, оценки, usage, latency и статус ошибки. Он записывается под существующей проверкой lease. Отключение пилота останавливает новые обращения; старые отчёты сохраняются. Ранжирование памяти и автоматическое отклонение фактов не реализованы.

- `GET/POST /api/developer/typesafe`: настройки, POST `{key?, clearKey?, pilotEnabled?}`.
- `POST /api/developer/typesafe/test`: явный короткий реальный запрос, даже при выключенном пилоте.
- `GET /api/developer/typesafe/results`: последние 20 отчётов.

## Воспроизводимые проверки

Используйте отдельную БД без реальных ключей, включая сохранённые. `DATABASE_URL` должен совпадать у скриптов и веб-сервера; `SMOKE_BASE_URL` указывает на работающий сервер.

Для `typesafe-smoke.ts` задайте `ARENA_ISOLATED_TEST_DB=1` и один синтетический `CHRONICLE_SECRET_ACTIVE_KEY`/`CHRONICLE_SECRET_KEYS` одновременно в окружении тестового веб-сервера и процесса smoke. Скрипт не создаёт локальную замену: без корректного keyring он откажется от записи; несовпадающий keyring отдельного сервера выявляется обязательной успешной HTTP-проверкой чтения, а не считается пройденным маскированием ошибки. Не используйте production keyring или production БД.

После введения административной роли этому smoke также нужен отдельный **тестовый** администратор: выберите неиспользуемый UUID `SMOKE_ADMIN_ACCOUNT_ID` и включите тот же UUID в `CHRONICLE_ADMIN_ACCOUNT_IDS` **и у тестового web, и у процесса smoke**. Настройте окружение до старта тестового сервера. Скрипт создаёт явно ограниченную fixture-учётную запись/сессию в изолированной БД, а не повышает роль гостя или первого посетителя. Существующий ID аккаунта использовать нельзя. Отсутствие роли, ответ 403/503 или несовпадающее шифрование должны приводить к провалу smoke; проверки HTTP 200 не отключаются ради прохождения.

```powershell
npm run typecheck
npm test
npm run lint
npm run build
node --env-file=.env --import tsx scripts/migrations-check.ts
node --env-file=.env --import tsx scripts/smoke.ts
node --env-file=.env --import tsx scripts/v22-smoke.ts
node --env-file=.env --import tsx scripts/typesafe-smoke.ts
npm run verify:story-ui
```

`typesafe-smoke.ts` использует настоящую тестовую PostgreSQL и mock HTTP-провайдеров: проверяет выключенный пилот, отказ, оценку «противоречит» без изменения канона и устаревший lease. `verify:story-ui` подменяет API только в браузере: поля, маршрутизация, повтор старого запроса, меню, чтение, диалоги, dirty guard и mobile. Эти проверки не измеряют качество реального AI.

## Реальная оценка моделей

24 сценария создания находятся в `tests/fixtures/story-draft-scenarios.json`. При настроенном Gemini:

```powershell
npm run eval:story-drafts -- --base-url=http://localhost:3000 --out=story-eval.json
```

Скрипт измеряет валидность, полноту, сохранение введённых полей и latency, проверяет идентификатор Lite. Согласованность требует ручного просмотра сохранённых patch: соответствует ли герой миру, учтены ли все ограничения, нет ли навязанного жанра/тона/профессии. В отчёте ручная оценка остаётся `pending-human-review`; структурный PASS не считается литературным качеством. Сравнение с Flash имеет смысл только при обнаруженных недостатках Lite.

60 размеченных русскоязычных примеров Jev охватывают подтверждение, отрицание, намерение, гипотезу и неоднозначность. CLI `npm run eval:typesafe -- --live` требует `TYPESAFE_API_KEY` и делает реальные запросы к провайдеру; запуск без `--live` проверяет корпус. Сохраняйте confusion matrix, ошибки, latency и usage, отдельно проверяйте русскоязычные ошибки: разработчик модели отмечает более высокое качество на английском. Автоматического порога отбрасывания фактов нет.

Официальные контракты: [Gemini Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [Jev System One](https://docs.typesafe.ai/concepts/system-one), [модели и языки](https://docs.typesafe.ai/models), [citation check](https://docs.typesafe.ai/cookbooks/citation_check).

Реальные Gemini/Jev evaluation в текущем окружении не выполнялись: ключи не предоставлены. Результаты mock-проверок не следует использовать как подтверждение качества этих моделей.
