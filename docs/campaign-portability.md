# Перенос кампаний

Владелец скачивает JSON через меню **Мои кампании → Скачать кампанию (JSON)** или кнопку JSON в игре. **Скачать журнал** остаётся Markdown для чтения, не для импорта. Полный JSON чужой публичной кампании недоступен; для неё используется отдельная функция приватной копии.

Импорт доступен после регистрации или входа в аккаунт. В **Мои кампании → Импорт кампании** выберите экспорт Chronicle до 4 МиБ. Гостю форма предлагает перейти к входу или регистрации; выбор файла и отправка доступны только аккаунту. Сервер проверяет версию, размеры, поля и ссылки, затем создаёт приватную активную кампанию текущего аккаунта. Переносятся сохранённые герой, мир, ходы, память и договорённости. Структурные идентификаторы заменяются. Ключи, настройки профиля, стоимость запросов, request IDs ходов, контрольные точки, задания и готовые векторы не переносятся. Новые задания эмбеддингов используют настройки и бюджет импортирующего владельца; импорт сам не вызывает провайдера.

Формат: `chronicle-campaign`, `schemaVersion: 1`. Контрольная сумма выявляет повреждения, но не является цифровой подписью и не доказывает правдивость импортированных утверждений.

Поля жизни мира из 2.7 (`clock`, `story`, `commitments`, `holdings`) и этапа 2.8 (`agenda`, `npcAgendas`, `narrator`, `conditionTimers`) входят в тот же снимок. Экспорт/импорт сохраняет и применённые последствия этих этапов в истории ходов. Их вложенные значения проверяются по строгой схеме с ограничениями размера и допустимых статусов; неизвестные поля отклоняются до проверки контрольной суммы. Старые документы без этих необязательных полей по-прежнему принимаются.

API: `GET /api/sessions/{id}/export?format=json`; `POST /api/sessions/import` с `{requestId, document, title?}`. Повтор той же попытки возвращает прежнюю кампанию; изменение документа/названия с тем же requestId даёт 409. После удаления результата повтор даёт 410, не воссоздаёт кампанию. Форма сохраняет requestId при сетевой ошибке и закрытии окна; повторный выбор файла означает новую попытку. Перезагрузка страницы теряет эту локальную попытку — прежде чем импортировать снова, проверьте список кампаний.

Ограничения действуют отдельно для каждого профиля: не более 10 существующих импортированных кампаний (`IMPORT_STORAGE_QUOTA`, 409), 20 новых импортов за последние 24 часа (`IMPORT_RATE_LIMIT`, 429) и 1000 новых импортов за всё время (`IMPORT_HISTORY_QUOTA`, 409). Удаление кампании освобождает место для существующих импортов, но не возвращает дневную или пожизненную попытку. Неуспешный импорт не расходует попытку. Записи успешных импортов, включая удалённые результаты, сохраняются постоянно; ранее принятые запросы проверяются до квот, поэтому повтор, конфликт и отказ после удаления сохраняют своё поведение при достигнутом лимите.

Для одного профиля одновременно выполняется один импорт. Конкурентная попытка сразу получает `IMPORT_BUSY` (409) и `Retry-After: 1`; повторите её с тем же requestId после завершения текущего импорта. Ожидание блокировки не удерживает соединение БД. Гостевой запрос получает `ACCOUNT_REQUIRED` (403).

Миграция `0013_campaign_imports` добавляется после существующих миграций. Полный экспорт читается из согласованного снимка БД; импорт и запись результата повтора выполняются одной транзакцией.
