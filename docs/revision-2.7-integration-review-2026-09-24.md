# Проверка и интеграция ревизии 2.7

Дата: **24 сентября 2026**

Проверки дополнены **26 сентября 2026**.

Источник: `revisions/2.7-revision`

Результат: выборочная интеграция с адаптациями в текущую ветку Chronicle Engine.

## Метод сравнения

Ревизия была рассмотрена как кандидатный снимок, а не как готовый merge. Сначала файлы были нормализованы по окончаниям строк, затем сравнивались только изменения поведения. В снимке текущего проекта было 358 файлов, в кандидатном — 359; после нормализации совпали 331 файл, 14 файлов имели существенные изменения, 13 были только в текущем дереве, 14 — только в ревизии. Остальные различия были изменениями CRLF/LF и не переносились.

Проверены все новые модули мира, взаимодействий и визуализации, API-контракты, схема Drizzle, журнал миграций, обработка хода, ownership, UI и тесты. Для каждой принятой части добавлены или расширены регрессионные проверки.

## Исправленные дефекты кандидатной реализации

Дополнение 26.09: административный выбор модели изображений реализован отдельной append-only миграцией `0015_visual_settings`, admin-only API и страницей `/system/visuals`. Сохранение принимает только canonical ID официальной text-to-image модели из текущего каталога Pollinations; новые изображения используют выбор, старые сохраняют модель из своей записи. Роль по-прежнему определяется UUID в серверном `CHRONICLE_ADMIN_ACCOUNT_IDS`, логин не служит источником полномочий. Внешнее качество и биллинг выбранных моделей локальными тестами не подтверждаются.

До переноса тестами и ревью были закрыты следующие случаи:

- действие над отсутствующим объектом, вещью или местом больше не считается доступным;
- передача NPC разрешается только в текущем месте, если у NPC уже известно другое место;
- возврат одной единицы не удаляет весь holding stack;
- количество передаваемого предмета проверяется до изменения состояния;
- некорректное время commitment отклоняется, а не превращается молча в `12:00`;
- размер ответа provider проверяется и по объявленному `Content-Length`, и по фактически прочитанному stream;
- гонка создания visual identity завершается корректной ошибкой, если конкурентная строка не появилась;
- очистка reference id сохраняется как `null`, а обновление визуала ограничено `visualId + sessionId`;
- seed использует безопасный fallback, когда глобальный Web Crypto недоступен в тестовом окружении.

## Принятые границы продукта

Изображение является иллюстрацией и не изменяет канон, инвентарь, отношения или результат хода. Сейчас нет фоновой durable-очереди изображений, exactly-once оплаты внешнего запроса, передачи приватного reference-файла провайдеру, второго адаптера, авто-предложений изображений или интерактивных hotspots. Эти пункты остаются отдельными задачами `VIS-0`, `VIS-2b`, `VIS-3` и `VIS-5` после измерений.

У визуального MVP есть сознательные ограничения: картинки хранятся как `bytea`, GET-список отдаёт метаданные без байтов, лимит резервируется на owner scope, а промпт собирается из ограниченного визуального описания. Политика публичной видимости сессий и долгосрочное object storage должны быть определены до внешнего запуска.

Эвристический parser взаимодействий распознаёт один основной intent, не моделирует все отрицания и не заменяет полноценную модель действий. Это безопасный baseline для кнопок и свободного текста, но не завершение `MECH-2`.

## Проверки

Свежая локальная проверка завершена:

- `npm run typecheck` — успешно;
- `npm run lint` — успешно;
- `npm test` — **408/408** тестов пройдено;
- `npm run build` — успешно с фиктивным `DATABASE_URL=postgresql://test:test@127.0.0.1:1/chronicle_build`; без переменной Next.js останавливается на обязательной инициализации DB-модуля, подключения к loopback не выполнялось;
- `npm run check:docs` — успешно: 43 документа, 99 локальных ссылок, npm-команды и migration ledger;
- `git diff --check` — успешно, только предупреждения о нормализации CRLF/LF.

Unit-проверки `tests/world-life.test.ts` включают старые состояния, clock, intent gate, доступность, передачу/возврат вещей, commitment/story boundaries, applied changes и provider size limits. `tests/visual-model-settings.test.ts` проверяет каталог и новую миграцию, `tests/admin-boundaries.test.ts` — роль, Origin и применение выбранной модели. Публичный каталог Pollinations прочитан без генерации изображения; платные вызовы Gemini/Pollinations, реальная PostgreSQL, платёжные лимиты, browser/a11y аудит новой вкладки и production deploy в этот отчёт не входят.
