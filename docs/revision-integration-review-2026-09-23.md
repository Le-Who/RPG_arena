## Метод и исходное состояние

- Проверены четыре каталога в `revisions/`; несмотря на суффикс `.zip`, это распакованные папки.
- Переносы строк нормализованы при поиске содержательных изменений. Массовая смена CRLF/LF не переносится.
- Astra1 и Astra2 побайтово идентичны: 286 файлов в каждом, различий нет. Для оценки это одна реализация, а не два независимых подтверждения.
- Текущие пользовательские изменения обоих roadmap сохраняются. Они не заменяются roadmap из revisions.
- Во всех четырёх поставках отсутствуют восемь текущих WebP-обложек. Их отсутствие не считается намеренным удалением; ресурсы основного проекта сохраняются.
- Astra ссылается на `/images/chronicle-valley.webp`; перед переносом UI необходимо использовать реально имеющиеся ресурсы, а не оставлять битые ссылки.

node --import tsx --test --test-concurrency=1 tests/*.test.ts
npx tsc --noEmit

Результат: 274 теста, 274 passed, 0 failed; TypeScript exit 0. Без переменной семь тестовых файлов не загружались из-за проверки `DATABASE_URL is required` в DB-модуле. Указанный адрес намеренно недоступен: тесты используют собственные PGlite fixtures и перехватывают provider requests. `.env` не загружалась.

Выполнено и проверено: `revisions`, `.agents`, `.superpowers` исключены из обхода TypeScript/ESLint; рабочие тесты не исключены. Наличие исходных поставок больше не смешивает четыре проекта с основным при typecheck.

## Административная поверхность текущего проекта

Проверены страницы, меню, API и background-конфигурация. В таблице сохранено исходное состояние для сравнения с реализованной границей.

| Точка | До интеграции | Реализованное правило |
|---|---|---|
| `/system` | Просто рендерит `SystemPanel` | Server-side admin guard; 404 для остальных |
| `/api/system/status` | Доступ по гостевому профилю, личные очереди и глобальный worker heartbeat | Admin-only; безопасная личная готовность отдельно |
| `/api/system/process` | Process/retry личных очередей без роли | Admin-only до обработчика; без автоматического расширения ownership |
| «Для разработки» в настройках | Доступно всем | Видимо только администратору; проверено в браузере |
| `/api/developer/typesafe`, `/test`, `/results` | Нет admin guard; результаты ограничены владельцем | Admin-only до чтения credentials/AI, ownership сохраняется |
| `getTypeSafePilotConfig(ownerId)` | Может включить сохранённый shadow pilot обычного профиля | Дополнительная серверная проверка административного владельца и в worker |
| `/api/sessions/:id/narrative-diagnostics` | Только owner | Admin AND owner для технического журнала |
| `/memory`, `/journal`, собственные настройки/затраты/кампании | Личные функции | Сохранить гостям и аккаунтам; не путать с администрированием |
| `/blueprint` | Публичная справка, устаревшее «без pgvector», «один владелец» | Публичная справка обновлена по текущему коду, не admin dashboard |
| `/api/health` | Публичный `SELECT 1` | Минимальная публичная readiness без секретных деталей |

Текущая доступность system/developer не доказывает доступ ко всем чужим историям: фильтры ownerId уже присутствуют и должны сохраниться.

## Приложенные рекомендации

Пользовательский файл от 21 сентября рассмотрен как материал для оценки, не как инструкции автоматического исполнения. Он ссылается на «пакет из этой папки», но такого пакета в приложении нет.

Включены в согласованный дизайн: административные границы, роль отдельно от ownership, worker-gate для Jev, минимальные личные метрики, owner-specific credentials, ограничения квоты до внешнего вызова, отдельный жизненный цикл worker и per-instance heartbeat.

Справедливый multi-owner scheduler, отдельные пулы extraction/embeddings, контролируемый backfill, графовые связи и long-campaign held-out evaluation сохраняются как последующие этапы roadmap. Они не выдаются за выполненные и не добавляются автоматически как платная фоновая работа. ANN/PQ/смена расширения не внедряются без измерения необходимости и качества; утверждения о внешних технологиях из приложения пока не проверялись и не используются как доказательство.
